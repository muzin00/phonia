# 学習データの採用手順

新しいコーパス、追加音素、抽出方法を学習へ導入する前に、自動チェックと必要に応じた試聴を行う。
判定対象は **コーパス・使用する話者／発話集合・音素範囲・抽出設定の組** とする。
データ量や自動抽出の成功件数だけで採用せず、実際の波形に対象音素が含まれることを確認する。

以下の100件レビュー・個別回答の保存・集計は、ユーザーが本格的なレビューを明示した場合に実施する。
通常の検証では少数区間の試聴で進め、毎回100件を聞くことや回答JSONLの保存を必須にしない。
試聴後の「OK」という発言だけで、品質所見のファイルや正式なレビュー・採用判断の記録を自動作成しない。
個別回答の保存・集計がないことを理由に、通常の検証や依頼された学習を止めない。

本格的なレビューの手順は、2026-10-10以降に新たに採用する学習データへ適用する。
既存実験の凍結済みデータや結果は、その実験で用いた条件の記録として保持する。

## 1. 候補と使用範囲を決める

コーパス名・版・取得元・利用条件・ファイルのSHA-256、話者ID、発話テキスト、収録条件を記録する。
使用する音素、原録音か復元音声か、含める発話種別も明示する。
話者のtrain／validation／test分割を先に固定し、採用判断用の抽出とレビューにはtrainだけを使う。
コーパス間の実在人物の重複を確認できない場合は、その制約を記録する。

## 2. 学習と同じ処理で抽出し、自動チェックする

予定しているテキストの音素変換・アライメント・波形処理を使って候補区間を生成する。
最低限、次を検査し、使用対象外になった件数と理由も保存する。

- 音声が読めて、必要なサンプルレート・チャンネル数・PCM形式を満たす。
- `start_sec < end_sec` で、区間が元音声の範囲内にある。
- 必要な区間長と、話者ごとの音素数を満たす。
- 元テキスト、期待音素列、アライメント、話者ID、元WAVの対応が追跡できる。
- 固定した無音・低音量の除外規則を満たす。

自動チェック前の全区間と、チェック後の学習候補を別manifestに記録する。
低音量などを一律に除外する場合は、その規則・設定値・除外件数を記録する。
アライメントが成功したことや、音量条件を満たしたことを、音素ラベルが正しい証拠とは扱わない。

## 3. 学習候補からレビュー用サンプルを固定する

**自動チェック後の学習候補**から、コーパスごとに原則100件を固定seedで重複なくランダム抽出する。
使用予定の音素ごとにほぼ同数を割り当て、複数話者を含める。seed・抽出規則・実際の内訳を保存する。
音素や話者の不足で予定件数を用意できない場合は、不足を記録して採用範囲を見直す。

元WAV、区間ID、音素ラベル、時刻、抽出設定、SHA-256をUIデータと対応づける。
長さ制限やトリミング、文脈の追加を行う場合は、学習へ渡す波形とレビュー対象の範囲が対応するようにする。
聞きやすい区間への入れ替えや、レビューの途中での再抽出は行わない。

自動除外された区間を原因調査のために聞く場合は、**診断用サンプル**として分ける。
その回答を、学習候補の品質率の分母に混ぜない。

## 4. 人間が区間と原音声を確認する

既存の[音素レビューUI](../tools/phoneme-review-ui/README.md)で、次の順に確認する。

1. 区間だけを再生し、表示された音素が聞こえるかを回答する。
2. 前後100msを含む再生と元発話で、音素の位置や切り出しのずれを確認する。
3. 学習区間として「利用できる」「利用できない」「判断できない」を回答する。
4. 「JSONLへ保存」で回答をファイルに保存する。

聞こえ方は「対象音素」「対象音素と隣接する音」「別の音だけ」「ほぼ無音」「判断できない」に分ける。
対象音素と共調音・遷移が含まれる区間は、その存在だけを理由に不適切とはしない。
短い子音や無声化母音を単独で聞き取れない場合は、直ちに誤ラベルと決めず、判断の不確かさを残す。
聴感レビューを音声学的な正解境界や、厳密なラベル精度とは扱わない。

元録音でも音が不明瞭なのか、原音声では確認できるのに切り出した区間が違うのかを区別して所見を残す。
前後100msの再生は位置確認の補助であり、その音声を学習へ追加したことにはしない。
録音環境の違いやノイズの存在だけで判定せず、予定する音素区間を利用できるかを確認する。

## 5. 集計し、採用・保留・除外を判断する

データセットID・版・区間IDごとの最新リビジョンを使い、未回答・スキップ・回答済み件数を分ける。
全体に加え、コーパス別・音素別の件数、レビューに含まれる話者数、次の割合を記録する。

| 指標 | 集計方法 |
| --- | --- |
| 聴感上の無音率 | 「ほぼ無音」の件数 ÷ 聞こえ方への回答件数 |
| 別音のみ率 | 「別の音だけ」の件数 ÷ 聞こえ方への回答件数 |
| 聞こえ方の判断不明率 | 「判断できない」の件数 ÷ 聞こえ方への回答件数 |
| 利用可能率 | 「利用できる」の件数 ÷ 総合判定への回答件数 |

割合には分子・分母を併記する。「判断できない」を除いて利用可能率を計算しない。
未回答やスキップを回答済みとして数えず、音素ごとの未確認範囲も明示する。
RMSによる低音量件数と、人間が「ほぼ無音」と回答した件数は別の指標として扱う。

**本格的なレビューを実施する場合は、人間がレビュー結果と所見を記録し、採用判断するまで新しい学習を開始しない。**
判定は以下のいずれかとし、対象範囲、判定者、日付、理由、参照する回答・集計を残す。

| 判定 | 判断と次の処理 |
| --- | --- |
| 採用 | 予定した音素範囲のレビューと集計が完了し、波形と音素の対応を利用可能と判断した。採用manifestと設定を固定する。 |
| 保留 | 未確認の音素がある、判断不明が多い、または無音・誤った音・境界ずれが繰り返す。原因を調べ、必要な範囲を再レビューする。 |
| 除外 | 現在の抽出条件では学習用に利用しないと判断した。対象と理由を記録し、次の学習条件から外す。 |

現時点では自動合否の数値閾値を設けず、回答内訳と音素別所見を根拠に人間が判断する。
数値閾値を導入する場合は、対象・分母・基準を次のサンプルのレビュー前に決める。
学習後のvalidation／test成績に合わせて採用基準を変更しない。

レビューした区間だけを手作業で採用することや、個別に境界を修正することは、この手順には含めない。
抽出方法や一律の品質規則を変更する場合は、新版として候補全体へ適用し、新たな固定サンプルで確認する。

## 6. 採用した入力を固定してから学習する

採用manifest、抽出設定、話者分割、元音声のSHA-256、レビューサンプル、回答JSONL、集計、採用理由をひとまとまりで保存する。
採用後のtrainだけで特徴統計を計算し、実際の学習入力が採用manifestと一致することを確認する。
使用コーパス、音素、抽出設定、品質規則、追加データの範囲が変わる場合は、変更部分をこの手順で再確認する。
過去の回答を上書きせず、レビュー対象や条件が変わった場合はデータセットIDまたは版を更新する。

## 2026-10-10の予備レビュー所見

今回の[学習前レビュー](../poc/phoneme-consonant-review/README.md)は、音量による除外前の `/m/`・`/n/` を対象にした。
上記の「自動チェック後の学習候補」の正式レビューとは区別し、採用前レビューを必須にするきっかけとして記録する。

| コーパス | 準備したサンプル | ユーザーによる聴取所見 | 今後の扱い |
| --- | --- | --- | --- |
| JVS | `/m/`・`/n/` 各25件、計50件 | 品質はとても良い。 | 採用候補。学習候補と使用する全音素の範囲を確認する。 |
| Common Voice日本語 | `/m/`・`/n/` 各50件、計100件 | 品質はOK。 | 採用候補。学習候補と使用する全音素の範囲を確認する。 |
| SRC4VC | `/m/`・`/n/` 各25件、計50件。再確認も同じ50件。 | 無音や別の音が聞こえる割合が多く、学習データからの除外候補。 | 採用保留。録音品質と切り出しの問題を調べ、必要なら再レビューする。 |

表の件数はUIへ用意した件数であり、回答済み件数ではない。
この所見を記録した時点では回答JSONLが保存されておらず、無音率・別音のみ率・利用可能率の定量集計は未実施。
母音はこの予備レビューの対象外で、SRC4VCの全音素の品質や過去の学習が伸びなかった原因を確定した結果とはしない。
