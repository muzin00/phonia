# Phase 5 照合設計 v1.0.0

## 目的と境界

保存済みユーザープロファイルと別の照合音声を比較し、母音別・統合の類似度スコアを返す。
共通encoder、特徴統計、登録済みプロファイルは更新しない。
この工程の成果物は照合処理と再現可能な結果JSONである。
認証性能の評価と閾値の決定はPhase 6、既存方式との比較はPhase 7で行う。

## 初期の判断

| 項目 | 初期仕様 | 理由 |
| --- | --- | --- |
| 比較対象 | 同じ母音の区間と登録ベクトル | Phase 3の比較条件を維持する |
| 区間スコア | L2正規化した128次元ベクトルのcosine similarity | Phase 3の単一区間照合と同じ計算 |
| 複数区間 | 全利用可能区間のスコアを母音内で算術平均 | 一部だけの選別や新しい学習を必要としない |
| 母音の統合 | 5母音スコアの等重み算術平均 | 母音の出現回数に左右されず、追跡しやすい基準を作る |
| 照合側の最低数 | 各母音1区間以上、全5母音必須 | 可変の母音集合でスコア条件が変わることを避ける |
| 低レベル区間 | Phase 4と同じ固定規則で除外 | 登録と照合の入力品質条件をそろえる |
| 登録との分離 | 元WAVパス・WAV checksum・区間IDが登録と異なることを検査 | 登録音声を照合に再使用する誤りを防ぐ |
| 出力 | スコアと計算根拠を含む版付きJSON | Phase 6と後日のレビューで再利用する |

正本は`config/verification-policy.json`。
これらは初期基準であり、5母音の等重みや照合区間数の最適性は未評価。
母音不足を許す方式、重みの較正、学習可能な統合方式は後続の比較設計で扱う。

## 計算

登録済み母音`v`の単位ベクトルを`r_v`、照合区間`j`の単位ベクトルを`q_vj`とする。

```text
区間スコア      s_vj = dot(r_v, q_vj)
母音スコア      s_v  = sum(s_vj) / n_v
統合スコア      S    = (s_a + s_i + s_u + s_e + s_o) / 5
```

各区間の特徴をfloat64へ変換しL2正規化した後、内積と算術平均をfloat64で計算する。
丸め誤差だけを補正するため、内積を`[-1, 1]`にclampする。
区間ID順に計算し、同じ入力集合の並べ替えで結果が変わらないようにする。
全区間を一度に平均する方式では、頻出母音が強くなる。
この実装では先に母音内で平均し、各母音の寄与を常に`1/5`とする。

照合側の特徴を平均して再正規化する方式は採用しない。
区間スコアの平均と平均ベクトルを再正規化したcosineは別の計算であり、
後者は照合側区間同士のばらつきの影響を変える。
照合側が各母音1区間なら、母音別の計算はPhase 3の単一区間cosineと一致する。
5母音をまとめたスコアはPhase 3の母音別評価にはなかった新しい条件なので、
Phase 3の閾値を流用しない。

## 入力検査と不足時の扱い

一つの照合入力は一人の一つの照合試行とする。同じ試行の複数発話にまたがる区間も扱える。
話者の同一性、母音ラベルや境界の正しさは上流の入力作成に依存する。
JVS動作確認で複数発話を使う場合は、その条件を結果報告に明記する。

- 元音声は24 kHz・モノラル・signed 16-bit PCM。frame範囲は終了を含まない。
- 同じPhase 3前処理を使用する。30 ms以上、250 ms超は中央crop、DC除去、
  RMS正規化なし、64-bin log-Melと保存済みtrain特徴統計を使う。
- 短区間、無音、元区間のraw RMSを小数点以下3桁へ丸めて-50 dBFS未満の区間を除外する。
  人手による個別選別や品質重みは使用しない。
- 除外後に一つでも母音が不足すれば、母音別件数・不足母音・除外理由を返す。
  部分スコアの保存や利用可能母音だけの平均は行わない。
- root外・絶対パス、未対応母音、不正な範囲、WAV形式・読込・checksum不一致は試行全体を停止する。
- 重複IDと同じWAV内容・frame範囲の重複入力を拒否する。別名のWAVコピーも重複として扱う。
- 登録入力と同じWAVパス・内容・区間IDは、登録で除外された区間も含め拒否する。
  同じWAV内の別区間も登録・照合には分けない。
- 登録側の相対パスは照合の`audio_root`を基準に解決するため、同じ音声rootを基準に入力を作る。
  登録音声の原本を削除しても、保存済みchecksumとベクトルだけで照合できる。
- 推論前に全入力と最低数を検査する。推論後に元WAVのchecksumを再検査する。

`load_profile(..., encoder=encoder)`と`verify()`で互換性を確認する。
checkpoint、encoder設定、特徴統計、前処理と共有実装の識別情報が一致しない場合は停止する。
CPU / float32 / batch=1の固定encoderを勾配無効で使用し、optimizerは構築しない。

## 結果形式と再現性

一試行につき一つのUTF-8 JSONを原子的に保存し、上書きは拒否する。

| フィールド | 内容 |
| --- | --- |
| `schema_version` / `verification_version` | 保存形式と処理の版 |
| `query_id` / `user_id` | 照合試行と照合先ユーザー |
| `profile_sha256` | 使用した登録プロファイルの内容checksum |
| `encoder` / `inference` / `runtime` | モデル・前処理の識別情報、実行条件とライブラリ版 |
| `policy` / `policy_sha256` / `implementation_sha256` | 計算規則と照合実装の識別情報 |
| `vowels` | 母音別スコア、登録区間数、照合区間数 |
| `verification_score` | 5母音の統合スコア |
| `segments` | 元WAV・checksum・frame範囲・使用/除外理由・区間スコア |
| `sha256` | このフィールド以外のcanonical JSONのchecksum |

時刻や結果の保存先は含めない。同じ入力・プロファイル・実装・実行環境なら、
入力順を変えても同じファイルを生成できる。異なるCPUやPyTorch版でのビット一致は保証しない。
再読込時はchecksum、版、件数、区間・母音・統合スコアの整合性を検査する。
`load_result(..., encoder=encoder)`でencoderとの互換性も検査できる。
Phase 6では正解ラベル、データ分割、試行の定義を別に管理し、結果と`query_id`で対応させる。

## 検証方針と後日の評価点

合成データのテストで既知のcosineと等重み統合、母音別件数の不均衡、不足・不正入力、
登録音声の再使用、結果の破損と再現性、モデル・特徴統計・プロファイルの不変を検査する。
実データでは学習外のvalidation話者の別音声を使い、本人音声と別人音声で処理を確認する。
この少数例の動作確認から認証精度や優位性は判断しない。

後日のレビューでは、まず全5母音必須の条件とスコア計算規則を確認する。
Phase 6に進む際は照合試行の単位、区間数、収録条件、閾値決定用データと評価用データの
分離を決めてから性能を測る。Phase 3の最終testを設計調整に使用しない。
