# Transformerの学習更新数を増やす比較

構成を複雑にせず学習量を増やす方法で改善するか、まず既存データでの追加更新を検証する。[前回の比較](../phoneme-corpus-transformer/README.md)の280ラベルencoderを固定したTransformerを引き継ぎ、4,000・16,000・64,000更新を3seedで評価する。新規データや本人の追加録音は使わない。

## 結果（2026-10-12）

全3seedを64,000更新まで継続し、3予算×選択/最終の18checkpointを評価した。**4,000→16,000更新では、validationで選んだモデルのtest EER平均が3コーパスとも改善した。64,000更新ではCVがさらに改善したが、JVS・JTubeは16,000更新より悪化し、単調な全体改善ではなかった。**

主結果は各予算内のvalidation最良checkpoint。数値は統合層3seedの平均±標本SDで、話者母集団の信頼区間ではない。

| 学習予算 | JVS EER | Common Voice EER | JTube EER |
| --- | ---: | ---: | ---: |
| 4,000更新 | 1.348±0.138% | 4.362±0.041% | 1.256±0.376% |
| 16,000更新 | 1.108±0.221% | 3.905±0.401% | 1.129±0.280% |
| 64,000更新 | 1.425±0.204% | 3.543±0.222% | 1.266±0.075% |

16,000更新の4,000更新に対する相対EER低下はJVS約17.8%、CV約10.5%、JTube約10.1%。JVSとCVは3/3seed、JTubeは2/3seedで改善した。64,000更新のCVは4,000更新より約18.8%低下し、3/3seedで改善した。一方、JVSは1seed改善・1seed同率・1seed悪化、JTubeは1seed改善・2seed悪化だった。

選択された更新数は、16,000予算で12,500・6,000・13,000、64,000予算で59,500・38,000・63,000。したがって表は「16,000または64,000更新の終点そのもの」の結果ではない。

終点を固定した副結果は次のとおり。選択モデルの結果と区別すると、追加更新だけで全コーパスが改善したとは言えない。

| 固定最終checkpoint | JVS EER平均 | Common Voice EER平均 | JTube EER平均 |
| --- | ---: | ---: | ---: |
| 4,000更新 | 1.179% | 4.501% | 1.671% |
| 16,000更新 | 1.195% | 4.060% | 1.222% |
| 64,000更新 | 1.315% | 4.101% | 1.363% |

CVの主結果の本人拒否率は55.704%→53.222%→52.296%へ低下した。他人受入率は0.497%→0.512%→0.521%で、test FARを揃えた比較ではない。Transformerを加える前の等重み対照はEER4.303%、本人拒否51.667%、他人受入0.195%だった。追加学習後はCVのEERも等重みより低くなったが、認証閾値での本人拒否まで対照を上回ったとは言えない。

JVSの主結果の本人拒否率は4.133%→3.556%→4.044%、JTubeは40.889%→40.778%→40.944%。採点率は全条件でJVS98.00%・CV64.56%・JTube59.83%のままで、追加学習による未採点の解消はない。

結論は、**同じ構成・同じデータでも、追加更新とvalidationによるモデル選択で改善する余地があった**ということ。64,000更新を一律の置換モデルにはしない。新しい話者・発話を増やすデータスケーリングは、今回の更新数比較とは分けて検証する。

## 固定した条件

設定は[config.json](config.json)。runは`artifacts/phoneme-transformer-budget/continued280-20261012-v1`。

- encoder、279ラベル・15,123 queryの統合層学習入力、登録/query分割、2層・4head・隠れ次元64のTransformer、損失、32 query/64照合のbatchを前回と共通にする。
- 3seedは20261015・20261016・20261017。各seedの**4,000更新最終モデル**、AdamW状態、乱数状態を復元する。validationで選択済みの最良モデルから継続するわけではない。
- 4,000更新までは前回の履歴を完全に保持する。以降は終盤の学習率に合わせた3e-5で64,000更新まで継続し、16,000更新時点も保存する。学習率の再上昇や、総更新数に合わせたcosine scheduleの引き伸ばしは行わない。
- 同じseedの16,000・64,000条件は同じ学習軌跡の先頭部分を共有する。既存の4,000更新分の照合ペアを保持し、以後4,000更新ごとに固定seedからペアを追加する。本人・他人で共通の音素maskを使用する。
- 500更新ごとに3コーパスの通常verificationのvalidation EERを測り、その等重み平均が最小のcheckpointを各予算内で選ぶ。同率は最も早い更新を選び、前回の最良checkpointも候補に残す。
- 主結果はvalidationで選択したモデル。同時に、各予算の固定最終checkpointも副結果として評価する。長い学習で選択候補が増える影響と、終点の性能変化を区別する。
- 3予算×3seed×選択/最終の計18checkpointを確定し、各モデル・各コーパスのvalidation FAR1%閾値を固定してから新しいtestスコアを計算する。testでのモデル選択や条件変更はしない。

これは**元の終盤の学習率を保った追加最適化**の比較である。長時間用に調整した学習率schedule、大きなモデル、新しい話者・録音を増やす効果は別の問いとして残る。改善しなくてもTransformer全般やデータ量のスケーリングが不可能とは結論しない。

EERは採点可能な照合に限定し、FAR/FRRは未採点を拒否として含む全入力で測る。全testは既観測。3seedは統合層の学習の違いで、encoderの再学習や独立の評価話者集団の追加ではない。

## 実行と検査

```sh
poc/phoneme-verification-evaluation/.venv/bin/python poc/phoneme-transformer-budget/run.py execute
poc/phoneme-verification-evaluation/.venv/bin/python poc/phoneme-transformer-budget/run.py status
poc/phoneme-verification-evaluation/.venv/bin/python poc/phoneme-transformer-budget/audit.py
```

3seedを独立したCPUプロセスで並行実行する。各プロセスは1スレッドで計算し、500更新ごとに再開用状態をatomicに保存する。最良モデルと現在のモデルを同じ保存境界から復元し、中断中に最良モデルのファイルだけが先へ進んでも整合性を保つ。学習中の進捗は約10分間隔で確認する。

新規3テストでは、照合順の先頭一致、予算内での最良checkpoint選択と同率処理、optimizer・乱数を含む中断再開後のモデル完全一致を確認した。元の実験コード・データ・checkpointは変更しない。

完了後の監査では全学習順を再生成し、4,000更新までの履歴・モデル・採点結果と元の実験の一致、選択の正しさ、全照合スコアの再推論、閾値と指標を検査する。出力は`results.json`・`results.md`・`complete-audit.json`へ保存する。

監査は完了し、validation/test合計2,166,000照合レコードの整合性を確認した。再推論スコアの最大差は0、元の4,000更新の選択モデルの保存済みスコアと今回の再評価は完全一致した。3seedの全学習順、optimizerの64,000更新、各予算内での選択、閾値、集計値も確認した。Ruff check/format checkと差分の空白検査も通過した。

`report.py`でseed内の差・標本SDを`paired-summary.json`へ集計し、`test-eer-by-budget.png`と`validation-learning-curves.png`を生成する。図のエラーバーは3seed間のSDで、信頼区間ではない。成果物と図はrun配下に保存する。

この比較の結論を得てから新しい学習データの追加を検討する。利用者から学習前の品質確認を希望されているため、新しいセットが決まった段階でレビューUIと対象範囲を提示する。過去のレビューを新しいセットの確認済み記録として流用しない。

既存のローカル配布目録も確認した。現在の学習・校正・testラベルを除くと、Common Voiceには日本語テキスト付き50発話以上の候補が107ラベル、JTubeには日本語リストで30発話以上の候補が77ラベルある。JTubeの50発話以上は残り4ラベルなので、従来の50発話条件を維持したまま話者数を大きく増やすことは、この配布目録ではできない。これらは未処理の候補数で、波形重複や音素抽出後の利用可能数ではない。新しい学習集合の選定・品質確認・追加学習はまだ行っていない。
