# CVだけに難例選択を適用する比較

前回の[全コーパスへの難例選択](../phoneme-hard-negatives/README.md)は64k選定モデルでCV EERを3.298→2.922%へ改善したが、JTubeを1.021→1.388%へ悪化させた。今回の目的は、CVの改善を保ちながらJTubeの悪化を抑えられるかを検証すること。

## 固定する条件

- 同じ420話者の確認済みデータ、216kの固定encoder、音響3 seeds（20260926/27/28）、Transformer seed 20261015。
- 同じ4k checkpoint・optimizer・RNGから再開し、16k/64k更新で保存。LR 3e-5、query順、バッチサイズ、モデル構造、正則化は変更しない。
- `random`は従来のランダム負例、`mixed`は前回の全コーパス難例選択、`cv_only`が今回の介入。
- CV照合枠は前回`mixed`の負例と完全一致させる。JVS/JTube照合枠だけ`random`の負例へ戻す。CV候補の再抽選や、別の枠への振り替えはしない。
- 前回は各更新32照合枠中16枠を難例選択にしており、今回はそのうちCVの枠だけ適用する。CV内で概ね半数であり、毎更新CV枠の厳密な半数ではない。
- train内のコーパスIDを負例選定に使うが、推論時のモデルや入力にコーパスIDを追加しない。共有Transformerのため、他コーパスへの影響がなくなる保証はない。
- 3コーパス平均validation EERで選定したモデルを主結果、最終checkpointを副結果にする。モデル36個を固定し、全validation閾値を固定してから新しいtestを採点する。

既観測testによる探索的な比較。CVだけの最良値で判断せず、JVS/JTube・等コーパス平均・固定閾値FAR/FRR・seed間の対応差も確認する。途中で予算や対象seedを変更しない。

対象をCVに限定すると難例の総数も減るため、この比較だけで「CVを対象にすること」と「全体の難例比率を下げること」の効果は分離できない。まずこの具体的な設定でCV/JTubeのトレードオフが改善するかを判断する。負例を変更すると、従来どおり本人/他人で共有する音素maskの内容も変わり得る。

## 実行・検証

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  poc/phoneme-verification-evaluation/.venv/bin/python \
  poc/phoneme-cv-hard-negatives/cv_only.py execute
```

既存実験のスクリプト・モデル・スコアを変更せず、新しいrunへ保存する。各seedで前回と同じCV枠・負例を保ち、非CVだけ元に戻ったことを全件検証する。候補・難易度計算は前回監査済み成果物をhashで固定して再利用。

学習前に新規2テスト（CV限定、非CV保持、入力非破壊、prefix/query不一致の拒否）と既存継続学習3テストを実行する。完了時に学習順、optimizer、選定、全評価スコアの独立再推論、両対照結果の完全再現を監査する。

成果物は`artifacts/phoneme-cv-hard-negatives/cvonly420-20261012-v1`。新しい録音・学習データは使用しない。

2026-10-12 18:22 JSTに3 workerで開始し、18:54に学習、19:03に評価・監査が完了。事前の新規2テストと既存継続3テスト、Ruff check/format checkは成功。CVでランダムから変更する負例数は283,238 / 283,109 / 283,082、非CVをランダムへ戻す数は556,743 / 556,617 / 556,541（音響seed順）。

## 結果

**CV限定の難例選択は、全コーパスに適用したときのJTube悪化をほぼ抑えた。ただし64kではCV改善も弱まり、学習量を増やすだけの安定した改善にはつながらなかった。** 16kの選定モデルでは、ランダム負例に対して3コーパスすべての平均EERが改善した。

以下は同じ音響3 seedsの平均test EER。低いほど良い。各コーパスに別モデルを選ぶのではなく、3コーパス平均validation EERで選んだ共通モデルを評価する。EERは採点できた照合のみを対象とする。

| 予算 | 評価データ | ランダム | 全コーパス難例 | CV限定難例 | CV限定の改善seed数（対ランダム） |
| ---: | --- | ---: | ---: | ---: | ---: |
| 16k | JVS | 1.331% | 1.386% | **1.118%** | 3/3 |
| 16k | Common Voice | 3.152% | 3.367% | **2.835%** | 2/3 |
| 16k | JTube | 0.914% | 1.090% | **0.845%** | 2/3 |
| 64k | JVS | 1.199% | 1.224% | 1.276% | 1/3 |
| 64k | Common Voice | 3.298% | 2.922% | 3.148% | 2/3（残り同値） |
| 64k | JTube | 1.021% | 1.388% | 1.041% | 1/3（悪化1、同値1） |

64kのJTubeは全コーパス難例より3/3 seedsで改善し、平均で−0.347 pp。元のランダムとの差は+0.020 ppまで縮まった。一方、CVは全コーパス難例より+0.226 pp悪化し、ランダムに対する改善幅も−0.376 ppから−0.150 ppへ縮小した。CVの改善を完全に維持できたわけではない。

| 予算・モデル | ランダムの等コーパス平均 | 全コーパス難例 | CV限定難例 |
| --- | ---: | ---: | ---: |
| 16k選定（主結果） | 1.799% | 1.948% | **1.599%** |
| 64k選定（主結果） | 1.839% | 1.845% | 1.822% |
| 16k最終（副結果） | 1.987% | 1.881% | 1.704% |
| 64k最終（副結果） | 1.943% | 1.656% | **1.583%** |

CV限定の選定モデルでは、16k→64kでCV EERが3 seedsすべて悪化した。等コーパス平均も1.599→1.822%。64k最終では逆に改善しているため、「長く学習すると必ず悪化する」とも断定できない。checkpointの選定を含めた安定性に課題が残る。testを見て主結果を最終checkpointへ切り替えない。

### SeedごとのCV EERと選定点

| 音響seed | CV限定16k選定 | CV限定64k選定 | CV限定64k最終 |
| ---: | ---: | ---: | ---: |
| 20260926 | 3.181% | 3.614% | 2.778% |
| 20260927 | 2.926% | 3.318% | 2.659% |
| 20260928 | 2.398% | 2.511% | 1.893% |

16k予算の選定更新は10,000 / 5,000 / 6,500、64kは28,000 / 51,500 / 60,000。いずれも介入前4kのモデルへの戻りではない。音響seedは3個だがTransformer seedは1個に固定しており、Transformer初期値への頑健性は未確認。

### 固定閾値の性能

validationでFAR1%を目標に固定した閾値をtestに適用。以下のFAR/FRRには未採点の拒否を含める。

| CV条件 | ランダムFAR / FRR | 全コーパス難例FAR / FRR | CV限定FAR / FRR |
| --- | --- | --- | --- |
| 64k選定 | 0.761% / 44.222% | 0.895% / 41.556% | 0.943% / 41.444% |
| 64k最終 | 0.943% / 42.556% | 1.373% / 37.519% | 1.368% / 37.778% |

CV限定64k最終のCV EERは2.443%と良いが、test FARは3 seedsすべて1%を超えた。16k選定もJTubeの平均test FARが1.289%であり、平均EERの改善だけでは運用条件の達成とは言えない。採点率は全条件共通でJVS 98.000%、CV 64.556%、JTube 59.833%。今回の変更で未採点の問題が改善したわけではない。

## 判断と次の検証

学習内の負例選択範囲を変えることで、CV/JTubeのトレードオフを調整できる証拠は得られた。今回の比較では**CV限定・16kが次の再現性確認の候補**になる。ただし平均の改善がすべてのseed・運用指標で揃ったわけではなく、既観測testによる探索結果なので標準モデルへの採用は保留する。

次はデータや学習時間を増やす前に、**Transformer seedを変えて16k/64kとcheckpoint選定の安定性を比較する**。今回まで固定していた初期化・学習順への依存を切り分け、同じvalidation選定規則と事前固定の最終checkpointを併記する。学習ペア、予算、判定規則を先に固定し、既存testに合わせて選定規則を調整しない。CV限定が有効な理由をさらに分離する場合は、同じ難例総数を全コーパスに配る対照が必要になる。この追加実験は未開始。
