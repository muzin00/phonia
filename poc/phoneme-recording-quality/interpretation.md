# 結論：録音条件への弱さは確認できた。Common Voiceとの差には発話長も関係する

**「Common VoiceはJVSより録音環境が悪そう」という観察は、次の改善を考えるうえで有用だった。同じJVS音声への介入で、現encoderが雑音・音量低下・帯域変化に弱いことを確認した。ただし、自然音声の比較からCommon Voiceの性能差を録音環境だけに帰属することはできなかった。短い発話と音素不足も大きな課題である。**

優先する改善検証は、**encoderの録音条件への頑健性と、有効発話長・音素量の確保**。母音受付条件の追加緩和や閾値調整だけでは解決しない。

## 1. Common Voiceは均一に悪いというより、ばらつきが大きい

学習話者のデータはJVS/Common Voice各70話者・各700発話、評価ではJVSの通常照合1,500発話とCommon Voiceの1,800発話を測定した。登録に使用した音声も別集計し、計6,901音声を解析した。測定対象はモデル入力と同じ24kHz PCMであり、Common VoiceのMP3変換の影響も含む。

以下はtest照合音声の中央値。括弧内は発話単位のP10〜P90で、信頼区間ではない。

| 指標 | JVS：750発話 | Common Voice：900発話 |
| --- | ---: | ---: |
| 有効音声長 | 4.77秒（3.40〜6.84） | 1.96秒（1.12〜4.58） |
| 有効区間RMS | −26.60 dBFS（−29.32〜−23.75） | −22.91 dBFS（−26.61〜−18.95） |
| 小音量フレームのRMS | −75.78 dBFS（−82.60〜−73.72） | −73.84 dBFS（−87.08〜−63.35） |
| フレーム音量のP90−P10 | 51.63 dB（46.87〜56.24） | 50.22 dB（41.86〜63.26） |
| クリッピング近傍sampleがある音声 | 0/750 | 7/900 |

Common Voiceには小音量フレームのエネルギーが高い録音やクリッピング近傍の録音があり、ばらつきも広い。一方、学習音声のenergy contrast中央値はJVS 51.49 dB、CV 52.53 dBで、一律にCVの雑音が多いとは言えない。quiet RMSとcontrastは無音処理・話し方にも左右され、真のSNRではない。

話者ごとの中央値を平均したtestのCV−JVS差では、有効音声長が−2.736秒（話者bootstrap 95%区間 −2.985〜−2.500）、音量が+3.585dB（+2.228〜+4.850）だった。quiet RMSとcontrastの差の区間は0を含んだ。録音環境と併せて、長さ・音量・音素構成の差を考慮する必要がある。

## 2. 同じ音声を加工すると、encoderの弱さが明確になった

JVSのvalidation/test各15話者から10発話ずつ固定選択し、testは各条件で本人150・他人2,100試行。登録音声・モデル・元JVS閾値を固定した。次の表では**元の音素境界と採用区間を固定**し、録音変化がencoderに与える影響を分離している。主診断は5母音必須。EERは採点可能入力、FAR/FRRは採点不能も拒否とする全入力である。

| 照合音声 | EER | 他人受入率 FAR | 本人拒否率 FRR |
| --- | ---: | ---: | ---: |
| 元音声 | 1.370% | 0.286%（6件） | 4.667%（7件） |
| 音量−12dB | 4.795% | 0.000%（0件） | 29.333%（44件） |
| 白色雑音20dB | 13.699% | 11.143%（234件） | 18.667%（28件） |
| 白色雑音10dB | 30.137% | 3.095%（65件） | 82.667%（124件） |
| 300〜3400Hz帯域制限 | 36.301% | 0.000%（0件） | 100.000%（150件） |
| 合成残響：RT60設定0.3秒 | 2.642% | 0.429%（9件） | 8.000%（12件） |

20dB雑音によるFAR増加は+10.857 pp、対応付き話者bootstrap 95%区間は[+5.208, +17.718] ppだった。元の音素境界を使っても悪化しており、音素抽出の修正だけで対処できる問題ではない。

10dB雑音で20dBよりFARが低いのは、本人まで大半を拒否するようになったためであり、頑健性が高まったわけではない。帯域制限のFAR 0%も、本人を全拒否する結果と併せて読む必要がある。0件の誤受入に対するbootstrap区間0〜0は真の誤受入率0を保証しない。

帯域制限はRMSを元音声に揃え、今回の全加工で量子化前クリッピングは0だった。それでも識別が崩れた。これは録音経路に対する感度の診断であり、CVが実際に300〜3400Hzへ制限されているという意味ではない。CVは4kHz超のpower比がむしろ高い音声も多かった。−12dBもCVの平均音量を再現した条件ではない。合成残響1条件の結果を実際の室内全般へ一般化しない。

## 3. 閾値と音素抽出を調整するだけでは十分に戻らない

加工条件ごとにvalidationで目標FAR 1%の閾値を決め、test加工前に凍結した診断も行った。20dB雑音・境界固定ではtest FAR 0.810%まで抑えられたが、FRRは54.667%へ上がった。帯域制限ではFAR 1.476%、FRR 96.667%。EER自体も悪化しており、閾値の移植失敗だけでは説明できない。

加工済み全波形をJuliusで再抽出すると、音量−12dBのFRRは境界固定29.333%から49.333%へさらに上がった。差+20.000 ppの95%区間は[+7.333, +36.000] pp。同じ境界でRMS基準だけ再適用した場合は33.333%で、抽出境界の変化にも影響がある。

20dB雑音の再抽出FAR/FRRは11.333%/19.333%で、境界固定と近かった。10dBでは150発話中16件がalignment失敗となり、再抽出FRRは90.000%になった。失敗音声を除外したり差し替えたりはしていない。

## 4. Common Voiceの短い発話は別の問題として扱う

前回のCV校正閾値をそのまま使用し、品質層の境界はvalidationだけから固定した。4母音以上のtest結果は次のとおり。

| 有効音声長の層 | 発話数 | 採点可能率 | FAR | FRR | EER |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短い：1.893秒未満 | 429 | 81.119% | 0.627% | 35.431% | 4.598% |
| 中間：1.893〜3秒未満 | 238 | 100.000% | 0.652% | 12.605% | 4.202% |
| 長い：3秒以上 | 233 | 100.000% | 0.651% | 12.446% | 4.292% |

長い層−短い層のFRR差は−22.985 pp、話者bootstrap 95%区間[−29.261, −15.909] ppだった。ただし同じ音声の長さだけを操作した比較ではないため、延長すれば必ずこの差だけ改善するとは言えない。EERの差が小さく、短い層の採点不能が多いことから、長さ・音素量の不足を優先して調べる根拠になる。

contrastが高い層でもFRR 29.293%・EER 6.103%で、低い層の20.524%・3.828%よりよくなかった。話者構成が異なり差の区間も広いので、単純な音量・quiet RMS・contrastだけで「良い録音を選べば解決する」とは言えない。

## 次に検証する改善

1. **音量・雑音・録音経路に対するencoderの頑健性。** まず登録/照合に同じ音量前処理を適用する場合と、学習側へ録音条件の拡張を加える場合を分けて比較する。既存encoderへの正規化だけで改善するとは仮定せず、clean性能の劣化も測る。今回の解析では前処理変更や再学習は行っていない。
2. **有効発話長と音素量の制御。** 同一話者・同一録音の長さを変える比較で、短さによる採点不能と識別力低下を分ける。受付母音数の追加緩和より、必要な音素量を満たす発話案内・再録音を候補にする。
3. **実録音での再確認。** 開発側で方式と閾値を固定した後、未使用話者と別日・別端末の録音で判定する。今回の観測済み評価集合を新しい独立testとは呼ばない。
