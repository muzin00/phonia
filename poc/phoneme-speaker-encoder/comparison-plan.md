# 候補比較計画

## 1. 方針

事前知識だけで一意に決めにくい入力、encoder、学習方法は、複数候補を実装して未知話者の
validation照合性能で選択する。単一項目だけを順番に固定すると項目間の相互作用を見落とす
ため、互換性のある候補は組み合わせて評価する。

比較に含める組み合わせは学習開始前に機械可読な設定一覧として固定する。結果を見た後に
候補を追加した場合は探索を別versionとして扱い、過去の順位表へ結果だけを追加しない。
ただしversionを変えても、同じvalidationへの適応による過適合が解消するわけではない。
今回の探索は`design_version = 2.0.0`とし、本比較、限定比較、診断を最初から区別する。
性能上の最適値は固定しない一方、評価手順と予算は結果を見る前に固定する。

## 2. 固定する条件

次は候補間で変更しない。

- 入力manifestと`near_silent`除外規則
- train / validation / testの話者分離と各role
- 最小区間長30 ms
- enrollment区間とverification trial
- checkpoint選択に使うvalidation macro EERの定義
- testを最終候補の3 seedを含む凍結済み評価bundleの一度の評価だけに使う規則
- 比較seed `20260926`、`20260927`、`20260928`

## 3. 組み合わせて比較する軸

性能差が期待でき、研究上の問いに直接関係する次の軸だけを組み合わせて比較する。

| 軸 | 候補 | 組み合わせ数への寄与 |
| --- | --- | ---: |
| 入力表現 | log-Mel、可変長生波形 | 系統を2分する |
| 音量正規化 | 上限付きRMS正規化あり、なし | ×2 |
| log-Mel encoder | 統計pooling + MLP、TDNN | log-Melだけ×2 |
| 生波形encoder | 初段kernel 80 sample、240 sample | 生波形だけ×2 |
| 損失 | AAM-Softmax、AAM-Softmax + 母音内SupCon | ×2 |

`poc/phoneme-speaker-encoder/config/baseline-log-mel.json`は参照候補であり、最終仕様ではない。
log-Mel encoderは`poc/phoneme-speaker-encoder/config/log-mel-encoders.json`を正本とする。
生波形用encoderは[生波形encoder設計](waveform-encoder-design.md)と
`poc/phoneme-speaker-encoder/config/waveform-encoders.json`を正本とする。

本比較の組み合わせ数は次の16通りである。

```text
log-Mel:  RMS 2 × encoder 2 × loss 2 = 8
生波形:   RMS 2 × encoder 2 × loss 2 = 8
合計:                                      16
```

全設定のconfig IDは`<input>__<encoder>__rms-<on|off>__<loss>`とする。
限定比較の`id`は検証目的のラベルであり、採用のtie-breakには同じ生成規則のconfig IDを使う。

## 4. 予算上1通りへ固定する軸

次の軸は予算上の仮定として参照値1通りに固定する。改善期待が小さいことを実証したものでも、
全候補に最適な値と確認したものでもない。固定値への依存は結果の制約として報告する。

| 軸 | 固定値 | 理由 |
| --- | --- | --- |
| log-Mel window / hop / bin | 25 ms / 5 ms / 64 | 最短30 ms区間で2 frameを確保する参照条件。別解像度の効果は未検証 |
| 最大入力長 | 250 ms crop | 長さ分布を参考にした予算上限。長区間への影響は条件別評価で確認 |
| embedding次元 | 128 | コンパクトな参照値。256次元等の改善余地は未検証 |
| 母音ラベル | encoderへの条件付けなし | 共通encoderの参照条件。母音条件付けの不要性を主張しない |
| batch sampling | `P=10, K=2` | 同母音negativeを多く確保し、positiveも各anchorに1件存在する |
| optimizer | AdamW、設計文書の共通値 | 候補間の比較条件を揃えるため |
| SupCon重み / temperature | 0.5 / 0.07 | 追加損失の参照点。別の強さ・温度での有効性は未検証 |

SupConのみの損失は予算上除外する。AAM-Softmaxを全候補に含め、指定した重み・temperatureで
母音内SupConを追加する価値だけを比較する。AAMは全train話者をclassとして全母音を学習し、
同母音内に限定するのはSupConの組と照合である。併用が不利でもSupCon全般を否定しない。

## 5. 限定比較と診断

### 5.1 全軸へ掛け合わせない2設定

次の2設定を学習前に登録し、70話者・同じ3 seedで必ず比較する。RMSあり・AAMのみの
参照点に限定し、本比較の同条件runを対照として再利用する。結果を見てから参照点を選ばない。

| 問い | 追加encoder | 対照 | 限界 |
| --- | --- | --- | --- |
| 時間混合の効果 | `framewise_cnn`（411,904 parameter） | `tdnn`（411,136） | 約0.19%の規模差。channel幅も異なるため完全な単一要因実験ではない |
| 生波形の長い時間文脈 | `waveform_cnn_k240_context27`（85.83 ms） | `waveform_cnn_k240`（16.50 ms） | context層・paddingも増えるため受容野だけの因果効果ではない |

MLP対TDNNはモデル全体としての性能・コスト比較であり、約6.24倍の規模差があるため
時間構造の効果だけを測る対照にはしない。限定比較の構造は各encoder JSONを正本とする。
長受容野は最短30 msでもmask付きsame paddingで実行でき、区間外の実音声は使用しない。

この2設定も最終採用対象に含める。採用対象は本比較16 + 限定比較2 = **18設定**である。
限定設定で未実施のRMS・lossとの相互作用は不明のまま残し、その組み合わせを勝手に採用しない。
方式全般の優劣ではなく、指定した探索範囲・学習レシピ内での構成選択と解釈する。

### 5.2 再学習不要の診断

70話者の全18設定・3 seedの選択済みcheckpointでvalidationを評価し、母音・長さ・登録数に
加えて無声化属性、品質フラグ、長母音属性を集計する。欠損はunknownとして残す。
採用設定には境界の±5 / ±10 ms平行移動と入力gain ±6 dBの感度診断も行う。
手順は[学習・評価設計](training-evaluation-design.md)に固定し、主trial・学習manifestを変更しない。
診断結果を理由に今回の候補や閾値を再選択しない。懸念が見つかった場合は制約として報告し、
運用採用の保留と次versionの検証課題にできるが、testを使って解決しない。

## 6. 実験順序と予算

1. 6 encoder実装で32区間過学習・有限値・padding不変性を確認する。
2. 本比較16設定と限定比較2設定を10話者・seed `20260926`で成立性確認する。
3. 18設定を70話者・3 seed・共通の最大更新数と停止規則・trialで比較する。
4. 採用規則に従って1設定を選び、その3 seedのcheckpointを保持する。
5. 採用設定だけ10・25・50話者を各3 seed、本学習と同じ最大30,000 update・停止規則で学習する。
   70話者の3 runを再利用し、10 / 25 / 50 / 70話者の入れ子学習曲線をvalidationで報告する。
   学習曲線は70話者で選択済みの構成に条件付けられた診断であり、候補再選択に使わない。
   特徴統計は各cohortだけで再計算し、AAM headのclass数以外のモデル条件は変えない。
6. 診断を完了し、設定・3 checkpoint・seed別閾値・test評価手順を凍結してからtestを一度評価する。

10話者cohortのEERだけで候補を除外しない。除外できるのは、構造上実行できない、数値的に
不安定、または事前に定めた計算資源上限を超える候補とする。性能による選択は70話者cohortの
validation結果で行う。

| 種別 | run数 |
| --- | ---: |
| 32区間過学習: 6実装 × 1 | 6 |
| 10話者成立性確認: 18設定 × 1 | 18 |
| 70話者本比較: 16設定 × 3 seed | 48 |
| 70話者限定比較: 2設定 × 3 seed | 6 |
| 採用設定の追加学習曲線: 3 cohort × 3 seed | 9 |
| 合計 | **87** |

従来68 runに対し、限定比較の実装確認2 + 成立性確認2 + 本学習6 + 学習曲線9 = 19 run増。
評価だけの診断・testは学習runへ数えないが、時間と推論回数は別途記録する。
87は全設定が成立した場合の計画値であり、失敗・中断・再実行も別欄に残す。

## 7. 採用規則

主順位は3 seedのvalidation macro EER平均が低い順とする。併せてseedごとの値、標準偏差、
母音別EER、cross-text、短区間性能、学習時間、推論時間、最大メモリ、パラメータ数を公開する。

3 seedが完了していない設定は順位を確定せず、欠落seedを平均から黙って除外しない。
主条件は`verification`・登録10区間。EERは0–1表記、丸め前のfloat64値を使う。
最小平均EERを`m`とし、`mean_eer <= m + 0.001`を実用上の許容候補集合とする。
0.001は0.1 percentage pointの予算上の許容差であり、統計的同等性の認定ではない。
集合内を次の値の昇順で辞書式に並べ、最初の1設定を採用する。

1. 主条件macro EERのseed間標準偏差（母標準偏差、ddof=0）。
2. cross-text macro EERの3 seed平均。
3. 30–49 ms区間macro EERの3 seed平均。
4. encoder parameter数（分類headを除く）。
5. 共通benchmarkでの推論時間の3 seed中央値。
6. 共通benchmarkでの最大メモリの3 seed最大値。
7. 一意なconfig IDのUTF-8辞書順。

副指標が逆転しても上記順序を変更しない。必須評価の欠損は事前検査で停止する。
bootstrapは候補と最小平均EER候補（同値ならconfig ID順の先頭）との差の95%区間を
対応付きで算出する報告専用の処理とし、
区間の重なりを採用規則へ使わない。15 validation話者と3 seedでは小さな差の確証に限界がある。
3 seedは3つの独立した評価話者集合ではない。bootstrap手順は学習・評価設計に定義する。

run内checkpointは最小主条件macro EER、完全同値なら早いupdateを選ぶ。seedの選抜は行わず、
選択設定の3 checkpointを各seed自身のvalidation閾値と対でtestへ持ち込む。
testはこの3 runの個別結果・平均・標準偏差を一度の凍結済み評価として報告し、ensembleしない。
単一配布モデルが必要な場合は性能を見る前に定めたseed `20260926`のcheckpointを使う。

全候補の結果を順位表へ残し、採用候補だけを報告しない。候補数が多いことによるvalidationへの
過適合は上記だけでは除去できない。小さな差を確定的優劣と解釈せず、test結果で再選択しない。

## 8. 探索空間の変更と結論の範囲

計算資源上限のため全組み合わせを実行できない場合は、結果を見る前に実行対象の削減規則を
決めて記録する。validation結果を見て都合のよい組み合わせだけ追加・削除しない。探索空間、
除外理由、未実行候補を成果物へ保存する。

資源上限（device、precision、run時間上限、メモリ上限）は実行環境確定時に
`execution-budget.json`として性能を見る前に記録する。未設定のまま比較を開始しない。
候補固有のハイパーパラメータ調整は次versionへ分離する。
既存の全発話speaker embeddingとの公平な比較はPoC Phase 7、別日・別端末評価は
データセットの第2段階に残す。今回のJVS結果だけで既存方式への優位性や実運用性能を主張しない。
