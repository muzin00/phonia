# 候補比較計画

## 1. 方針

事前知識だけで一意に決めにくい入力、encoder、学習方法は、複数候補を実装して未知話者の
validation照合性能で選択する。単一項目だけを順番に固定すると項目間の相互作用を見落とす
ため、互換性のある候補は組み合わせて評価する。

比較に含める組み合わせは学習開始前に機械可読な設定一覧として固定する。結果を見た後に
候補を追加した場合は探索を別versionとして扱い、過去の順位表へ結果だけを追加しない。

## 2. 固定する条件

次は候補間で変更しない。

- 入力manifestと`near_silent`除外規則
- train / validation / testの話者分離と各role
- 最小区間長30 ms
- enrollment区間とverification trial
- checkpoint選択に使うvalidation macro EERの定義
- testを最終候補の一度の評価だけに使う規則
- 比較seed `20260926`、`20260927`、`20260928`

## 3. 組み合わせて比較する軸

性能差が期待でき、研究上の問いに直接関係する次の軸だけを組み合わせて比較する。

| 軸 | 候補 | 組み合わせ数への寄与 |
| --- | --- | ---: |
| 入力表現 | log-Mel、可変長生波形 | 系統を2分する |
| 音量正規化 | 上限付きRMS正規化あり、なし | ×2 |
| log-Mel encoder | 統計pooling + MLP、TDNN | log-Melだけ×2 |
| 生波形encoder | 1D encoder 1種類 | 生波形は×1 |
| 損失 | AAM-Softmax、AAM-Softmax + 母音内SupCon | ×2 |

`poc/phoneme-speaker-encoder/config/baseline-log-mel.json`は参照候補であり、最終仕様ではない。
生波形用encoderは具体的な構造を設定として固定するまで実験を開始しない。

組み合わせ数は次の12通りである。

```text
log-Mel:  RMS 2 × encoder 2 × loss 2 = 8
生波形:   RMS 2 × encoder 1 × loss 2 = 4
合計:                                      12
```

## 4. 1通りへ固定する軸

期待できる性能差に対して組み合わせ数の増加が大きい次の軸は、参照値1通りに固定する。

| 軸 | 固定値 | 理由 |
| --- | --- | --- |
| log-Mel window / hop / bin | 25 ms / 5 ms / 64 | 最短30 ms区間でも2 frameを確保し、10 ms hopの計算削減が小さい |
| 最大入力長 | 250 ms crop | 全区間の99.9%を保持し、切り詰めなしとの差が生じる区間が少ない |
| embedding次元 | 128 | 70話者のPoCでは256次元による改善期待より計算量増加が大きい |
| 母音ラベル | encoderへの条件付けなし | 同母音内でlossと照合を行うため追加条件付けの改善期待が小さい |
| batch sampling | `P=10, K=2` | 同母音negativeを多く確保し、positiveも各anchorに1件存在する |
| optimizer | AdamW、設計文書の共通値 | 候補間の比較条件を揃えるため |

SupConのみの損失は除外する。安定した話者分類基準であるAAM-Softmaxを全候補に含めた上で、
母音内SupConを追加する価値だけを比較する。

## 5. 実験の進め方

1. 各候補で32区間の過学習、有限値、padding不変性を確認する。
2. 各組み合わせを10話者cohortで実行し、学習と評価が成立しない構成を特定する。
3. 成立した互換な組み合わせを70話者cohortで評価する。
4. 各組み合わせを同じ3 seed、更新数、trialで比較する。
5. validationで最終候補を一つ選び、設定とcheckpointを凍結する。
6. 凍結後に限りtestを一度評価する。

10話者cohortのEERだけで候補を除外しない。除外できるのは、構造上実行できない、数値的に
不安定、または事前に定めた計算資源上限を超える候補とする。性能による選択は70話者cohortの
validation結果で行う。

12通りを3 seedで本学習するため、70話者cohortは36 runとなる。10話者cohortの成立性確認を
各組み合わせ1回行うため、比較に関する学習は合計48 runである。32区間の過学習確認は
個々のハイパーパラメータ組み合わせではなく、MLP、TDNN、生波形1D encoderの実装ごとに
1回ずつ行う。

## 6. 採用規則

主順位は3 seedのvalidation macro EER平均が低い順とする。併せてseedごとの値、標準偏差、
母音別EER、cross-text、短区間性能、学習時間、推論時間、最大メモリ、パラメータ数を公開する。

平均macro EERの差が`0.001`未満、または話者単位bootstrapの区間が大きく重なる候補は同等と
みなす。同等の場合は次の順で採用する。

1. seed間のばらつきが小さい。
2. cross-textと30–49 ms区間の性能がよい。
3. パラメータ数、推論時間、最大メモリが小さい。
4. 前処理と実装が単純である。

全候補の結果を順位表へ残し、採用候補だけを報告しない。候補数が多いことによるvalidationへの
過適合を避けるため、小さな差を優劣と解釈せず、test結果を使った候補の再選択は行わない。

## 7. 探索空間の変更

計算資源上限のため全組み合わせを実行できない場合は、結果を見る前に実行対象の削減規則を
決めて記録する。validation結果を見て都合のよい組み合わせだけ追加・削除しない。探索空間、
除外理由、未実行候補を成果物へ保存する。
