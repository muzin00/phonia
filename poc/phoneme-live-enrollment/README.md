# 登録短縮と本人・他人候補の分離

利用者の意向により新しい録音は一旦終了する。本人識別の可能性を確認できたため、保存済みデータだけで登録負担の削減を検証する。

先行の[登録量診断](../phoneme-live-analysis/README.md)は本人スコアのみを比較した。今回は同じ先頭5・10・15・20録音からプロフィールを再構成し、[他人候補の参考照合](../phoneme-live-impostor/README.md)と同じCommon Voice test 60 clientラベル・1,800開始点も採点する。登録順を変更せず、練習音声や照合音声を登録へ追加しない。母音各10区間の登録条件に不足する5録音は不成立として残す。

主比較は各プロフィールの全登録音素（native）、副比較は成立した全プロフィールの共通音素（common）。後者は音素集合が変わる影響を分けるための診断であり、運用への音素選別ではない。照合は5母音がそろうまで最大3発話をまとめる既存adaptive1と同じ。本人の中断・未採点も全件残す。

20録音の校正群で既に固定した参考閾値2つを、そのまま全条件へ適用する。短縮条件ごとの再校正やtestに合わせた閾値調整はしない。基準20録音に対する対応付きスコア差、受入→拒否・拒否→受入の件数、本人最低値と他人候補最高値の差、録音時間を報告する。共通音素条件はスコア定義が異なるため、閾値での受入も診断として扱う。

本人は1人・同日4採点で、他人候補は環境・文章が異なる既観測集合。発話の再利用があり、独立した1,800試行ではない。短縮時に今回の分離を維持できても、登録10回の一般的な十分性や運用精度を保証しない。元の20回登録、モデル、マイクUI、認証閾値、デバイス条件は変更しない。

入力・既存結果・解析コードを固定してから実行する。元のプロフィール・本人スコア・20録音の他人候補スコアとの一致と、キャッシュembeddingの再推論一致を確認する。raw音声やembeddingはGitに含めない。

```sh
OMP_NUM_THREADS=1 poc/phoneme-alignment-evaluation/.venv/bin/python poc/phoneme-live-enrollment/compare.py freeze
OMP_NUM_THREADS=1 poc/phoneme-alignment-evaluation/.venv/bin/python poc/phoneme-live-enrollment/compare.py run
```
