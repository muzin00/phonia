# Common Voiceの追加学習による悪化の切り分け

[データ量・更新数・encoder seed比較](../phoneme-data-budget/README.md)をPR #80でマージ後、既存の凍結済み学習履歴とスコアで原因調査を開始した。ここで扱う「悪化」は、主に420話者条件のTransformer 16k→64k更新でtest EERが上昇する現象。280→420のデータ追加自体は、同じ216k/16k予算でCV平均EERを4.408→3.152%へ改善している。

## 現時点の結論

**追加学習で悪化した選定モデル3条件すべてで、本人ペアのスコア変化は改善側、他人ペアのスコア変化は悪化側に寄与していた。** 固定encoder上で学習した音素重み付けが、CV testの他人同士を分離する性能を悪化させている。等コーパス平均による選定のトレードオフだけでは説明できず、CV validation自体の改善もtestに再現していない。

均等重みを混ぜる介入では一部を緩和できたが、同じ介入を16k/64k両方に適用しても追加更新の平均悪化は残った。重み集中だけを単一原因とせず、混同しやすい他人ペアの学習と、話者に対する選定の汎化を次の検証対象にする。録音品質・過学習・容量不足のどれが根本原因かまでは特定していない。

今回の操作は既存成果物の読み取りと別ディレクトリへの診断結果保存のみ。学習、閾値変更、モデル採用変更は行っていない。すべて既観測testの探索的診断であり、このtestを使って次の主結果モデルを選ばない。

## 1. Validationでの改善がtestに再現していない

420話者、音響encoder 3 seeds平均、Transformer seed固定。選定は従来どおり3コーパスのvalidation EER平均最良。

| encoder更新 | Transformer予算 | CV validation EER | CV test EER |
| ---: | ---: | ---: | ---: |
| 216k | 16k | 3.210% | 3.152% |
| 216k | 64k | 2.839% | 3.298% |
| 432k | 16k | 3.245% | 3.337% |
| 432k | 64k | 2.896% | 3.567% |

432kでは16k/64kとも3/3 seedsで、選定checkpointのCV validation EERが予算内のCV単独最小値にも一致する。64kの6条件全体でも5/6条件が一致し、残り1条件の差は0.122 ppにとどまる。従って「JVS/JTubeを優先してCVのvalidationを犠牲にした」という説明は主要因にならない。最小値が同じcheckpointは複数あり得るため、CV単独選定と常に同じ更新が選ばれるという意味ではない。

選定候補数は更新0を含め33→129に増える。同じ30話者のvalidationを繰り返し見て最小値を選ぶことによる楽観性は候補となる説明だが、今回の観測だけで選定への過適合と分布差を区別できない。

## 2. 最終checkpointでもseedによって傾向が異なる

表はCV test EERの変化（64k − 16k）、単位はパーセントポイント。正は悪化。seedは音響encoderの初期値と学習サンプリングを変える。Transformer seedは固定。

| encoder更新 | 音響seed | validation選定 | 最終checkpoint |
| ---: | ---: | ---: | ---: |
| 216k | 20260926 | −0.160 | −0.380 |
| 216k | 20260927 | +1.033 | +0.493 |
| 216k | 20260928 | −0.433 | −0.463 |
| 432k | 20260926 | −0.012 | −0.647 |
| 432k | 20260927 | +0.344 | +0.386 |
| 432k | 20260928 | +0.356 | −0.760 |

216kでの平均悪化はseed 20260927の悪化が他2 seedsの改善を上回るため。432k・seed 20260928では選定モデルと最終モデルで方向が反転する。432k/64kのCV平均は選定3.567%、最終3.098%だが、最終に統一すればすべて解消するわけではない。seed 20260927は両encoder予算の最終モデルでも悪化している。

seed 20260927の選定16k→64kでは、照合側の30話者を1人ずつ除いてEERを再計算しても全30通りで悪化が残った。216kでは+0.877〜+1.180 pp、432kでは+0.163〜+0.407 pp。特定の照合話者1人だけによる結果ではない。最終16k→64kでも両予算の全30通りで悪化が残った。

補助指標として、同じ照合音声で「本人スコアが最も高い他人スコア以下」になる件数も確認した。seed 20260927・216kの選定モデルでは581件中18→31件（新規失敗16、回復3）。ただしこれは固定30人の候補内の順位であり、認証EERや運用時の失敗率とは別指標。

話者を除く感度分析では登録側30話者を固定しており、話者完全除外の交差検証・信頼区間ではない。悪化seedを結果から除外して平均を作り直さない。

## 3. Validationとtestの構成も同じではない

CV validation/testは互いに重複しない30話者ずつ、照合音声900件ずつ。採点可能なのはvalidation 679件（75.444%）、test 581件（64.556%）。全モデルで評価レコードのID・ラベル・未採点位置が同じことを確認したため、更新前後で採点対象が変わったことがEER悪化の原因ではない。

採点可能音声の抽出済み音素区間から集計した中央値は次のとおり。

| 指標 | validation | test |
| --- | ---: | ---: |
| 音素種類数 | 16 | 16 |
| 音素区間数 | 43 | 40 |
| 音素区間の合計時間 | 2.88秒 | 2.62秒 |
| 音素区間RMSの平均 | −25.98 dBFS | −26.55 dBFS |

合計時間は抽出された区間の合計であり、録音全体の長さではない。RMSは音量でありSNR・雑音量・録音品質を表さない。利用者の「CVはJVSより録音環境が悪い」という観察は仮説として保持するが、この表で裏づけられたとはしない。話者や発話構成の差は確認できるが、それがcheckpoint順位の逆転を起こしたという因果までは確定できない。

### 利用者からの追加仮説：母音区間の品質

2026-10-12に「Common Voiceの母音波形区間の質が悪く、追加学習時の悪化につながるのではないか」という仮説が提示された。未検証の仮説として保持する。区間境界・継続時間・クリッピング・音量・有声性などの代理指標と、識別誤りやスコア変化との関係は既存データから調査可能。ただし音量を雑音量と読み替えたり、相関だけで原因と断定したりしない。聴感や切り出しの正しさの確認にはレビューUIでの人手確認も組み合わせる。

まず負例選択の改善をTransformer seedを変えて確認する。再現しない場合はこの品質仮説を次の切り分け候補とする。改善が再現しても品質仮説を否定したことにはならない。元の録音の品質、母音区間の切り出し誤差、抽出後の前処理は区別して検証する。

## 4. 音素重みの集中と均等化の介入

420の全6 encoder条件、4つの保存済みTransformer、validation/testで重みを取り出した。モデルが出す音素スコアの加重平均係数であり、Transformer内部のattentionではない。

本人ペアの最大音素重みの中央値は16k選定時に約99.1〜100%、64k選定時には全条件でほぼ100%。有効音素数 `1 / sum(weight²)` の中央値もほぼ1になった。ただし16k時点から集中しており、改善するseedでも同様なので、集中の存在だけで悪化を説明できない。

学習済み重みと利用可能音素の均等重みを0/25/50/75/100%で混ぜた。入力音声・encoder・採点対象は固定し、追加学習はしていない。以下は事前に含めた50%介入と元モデルの比較。各セルは音響3 seeds平均のCV EER。

| encoder | Transformer選定予算 | 元validation | 50%均等化validation | 元test | 50%均等化test |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 216k | 16k | 3.210% | 3.367% | 3.152% | 2.987% |
| 216k | 64k | 2.839% | 2.932% | 3.298% | 3.211% |
| 432k | 16k | 3.245% | 3.389% | 3.337% | 3.260% |
| 432k | 64k | 2.896% | 3.020% | 3.567% | 3.385% |

64k選定モデルのtestは6条件中4条件で改善、2条件で悪化した。均等化は平均を緩和するが、16k/64k両方に同じ50%を適用しても、追加更新で2.987→3.211%、3.260→3.385%と悪化が残る。validationは平均で悪化しており、既存validationでこの介入を選ぶ根拠も弱い。testで最良の混合率を選んだり、改善済みモデルとして採用したりしない。

## 5. 他人ペアのスコア変化がEER悪化を上回っている

本人ペアと他人ペアのスコアを別々に16k→64kへ置き換え、置換順を入れ替えた2通りの寄与を平均した。2つの寄与の和は実際のEER差に一致する。正解ラベルを使う診断専用操作なので、実運用可能なモデル・推論方法ではない。以下はtestの選定モデル。

| encoder | seed | 本人スコア変化の寄与 | 他人スコア変化の寄与 | 実際のEER差 |
| ---: | ---: | ---: | ---: | ---: |
| 216k | 20260926 | −0.282 pp | +0.122 pp | −0.160 pp |
| 216k | 20260927 | −0.264 pp | +1.297 pp | +1.033 pp |
| 216k | 20260928 | −0.356 pp | −0.077 pp | −0.433 pp |
| 432k | 20260926 | 0.000 pp | −0.012 pp | −0.012 pp |
| 432k | 20260927 | −0.122 pp | +0.466 pp | +0.344 pp |
| 432k | 20260928 | −0.223 pp | +0.579 pp | +0.356 pp |

悪化した3条件はすべて、本人ペアの変化では改善しているのに他人ペアの変化がそれを上回って悪化する。seed 20260927では最終checkpoint同士でも同じ傾向だった。スコア分布変化の数学的な分解であり、学習上の原因を因果推定した値ではない。

補助的な順位失敗でも一致した傾向が見られる。seed 20260927・216kで新たに失敗した16音声は12話者に分散。64kで最も高くなった他人を両モデルで共通の比較相手に固定すると、本人スコア変化は平均−0.0009、他人スコア変化は+0.1375だった。各音素の重み×スコアの変化を合計して、この差を誤差1e-12以内で再現した。

新規失敗は抽出区間合計時間・区間数・RMSの全四分位に分布していた。区切りはvalidationから固定した。少数例の探索的集計であり、特定の音素・短さ・小音量・雑音だけを原因にする証拠は得られていない。

## 6. Validation話者分割での順位安定性

validationの30話者を15/15に200通り分割した。分割間で登録話者と照合話者の両方を分離し、それぞれの15人の候補内でEERを再計算した。下表は16k/64k選定モデルの比較。

| encoder | seed | 64kが改善した半分割数 / 400 | 両半分割で優劣が逆転した組 / 200 |
| ---: | ---: | ---: | ---: |
| 216k | 20260926 | 273 | 91 |
| 216k | 20260927 | 352 | 13 |
| 216k | 20260928 | 269 | 77 |
| 432k | 20260926 | 366 | 15 |
| 432k | 20260927 | 319 | 55 |
| 432k | 20260928 | 209 | 93 |

同値は改善にも逆転にも含めない。条件によって話者構成への依存が強い。一方、testで最も悪化したseed 20260927・216kはvalidation半分割の88%で64kが改善した。したがって「validationを単に分割すれば悪いcheckpointを確実に避けられる」とも言えない。

保存済みcheckpointは元々validation全体で選ばれているため、この分割は独立した選定・確認ではなく感度分析。200通りは同じ30話者を再利用しており、独立200実験や信頼区間として扱わない。

## 次に絞る検証

優先するのは、**混同しやすい他人ペアを学習に含める比較**。現行`inputs.py::make_schedule`は同じコーパスの別話者を一様ランダムで1人選んでいる。悪化が他人側に現れた今回の結果から、train内で複数の別話者候補を比較し、高スコアの他人を一定割合含める方法を検証候補にする。これが原因だった、あるいは必ず改善するとはまだ言えない。

次の学習ではランダム負例を対照に、encoder・データ・seed・更新数・学習率を揃える。testの話者やスコアを負例選定に使わず、validationを使ったcheckpoint選定と固定最終checkpointを引き続き分けて報告する。正則化強化や候補checkpoint数の削減を同時に変えず、まず負例選定だけを切り分ける。新しい本人録音・外部話者録音は不要。

この比較は[難しい他人ペアを増やす実験](../phoneme-hard-negatives/README.md)として完了した。64k選定モデルのCV EERは3.298→2.922%、3/3 seedsで改善した一方、JTubeは1.021→1.388%へ悪化した。負例選択を変える改善余地は確認できたが、全コーパス共通の標準設定には採用していない。詳細と運用指標は同実験の結果を参照。

全500更新刻みのvalidation EER履歴は残っているが、全checkpointの重み・testスコアは保存されていない。この調査で比較できるtestはencoder単体と各予算の選定/最終モデルであり、途中のtest推移を推測して補完しない。

## 再現と検証

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  poc/phoneme-verification-evaluation/.venv/bin/python \
  poc/common-voice-degradation/analyze.py
```

12 encoder条件×5モデル×2 split、計3,240,000件を読み、CVのEERを再計算した。testの元集計、およびvalidationの該当学習履歴との差はいずれも0。全条件の評価ID・ラベル・採点可否の一致、validation/test話者の非重複を検証した。

140入力・コードファイルのSHA-256を保存し、終了時にも変更がないことを再確認。前回監査に直接記載された121ファイルはそのhashとも一致した。Ruff check / format checkを実行した。モデル再推論の監査は前回完了済みであり、今回は保存済みスコアの診断。

詳細は[analysis.json](../../artifacts/common-voice-degradation/frozen-scores-20261012-v1/analysis.json)、全条件の表は[results.md](../../artifacts/common-voice-degradation/frozen-scores-20261012-v1/results.md)。生成結果はGit管理外。

追加調査は以下の順で再現できる。

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  poc/phoneme-verification-evaluation/.venv/bin/python \
  poc/common-voice-degradation/weights.py
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  poc/phoneme-verification-evaluation/.venv/bin/python \
  poc/common-voice-degradation/transitions.py
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  poc/phoneme-verification-evaluation/.venv/bin/python \
  poc/common-voice-degradation/score_shift.py
```

`weights.py`は介入手順・分割seed・コードhashを実行前に固定し、48通りの推論で採点可能907,200ペアを再計算した。保存済みスコアとの差は0。重みの総和、利用不可音素の重み0、100%均等化とencoder単体スコアの一致も検証。137ファイルを記録し、モデルhashは元の凍結情報とも照合した。`transitions.py`はキャッシュ重みのhashと音素寄与合計、`score_shift.py`は評価ID・採点可否・2寄与の和を検証した。既存の認証閾値や成果物は変更していない。
