# 母音区間支援レビューUI仕様

## 1. 目的

アライナーが出力した母音区間を、音声学の専門知識を前提にせず、同じ表示・再生条件と選択式設問で確認できる環境を提供する。

レビュー担当者には精密な境界時刻の入力を求めない。モデルが提示した区間について、対象母音を聞き取れるか、利用できないほど切れていないか、別の母音の核を含んでいないか、子音などの非母音成分が利用上問題になる程度かを視覚と聴覚の両方で判断してもらう。

母音区間は、対象母音の音響的な実現を含み、別の母音の核を含まない連続区間とする。前後の子音との遷移や共調音が聞こえることは許容し、音声学的に純粋な母音定常部だけを要求しない。

## 2. 対象外

- 音声学的に厳密な正解境界の作成
- 波形編集
- モデル出力の直接修正
- 一般ユーザー向けの製品UI
- アライナーの実行やモデル管理を行う管理画面

## 3. レビュー単位

レビュー単位は、期待音素列の一つの母音または同一母音が連続する`vowel_run`とする。

同じ母音が連続する場合は、モデルが出力した内部境界ではなく、結合した区間の外側を候補として表示する。異なる母音が連続する場合は別のレビュー単位とする。

各レビュー単位には次の情報を持たせる。

- `utterance_id`
- 発話テキスト
- 期待母音
- 発話内の母音位置
- 長音、無声化候補などの属性
- 元音声のパスまたはローカル配信用URL
- 候補ごとの開始時刻と終了時刻
- 表示用候補IDと実際の方式名の対応
- 自動検査結果とレビュー理由

方式が対象母音を出力できなかった場合は、存在しない区間を推測して表示しない。該当方式を`missing`として記録し、残りの候補だけを表示する。

## 4. 画面構成

### 4.1 発話コンテキスト

画面上部に次を表示する。

- `utterance_id`と進捗
- 発話テキスト
- 確認対象に対応する文字または語の強調表示
- 期待母音
- `vowel_run`の場合は連続する期待音素数

### 4.2 波形とスペクトログラム

- 元音声の対象区間前後を波形で表示する
- 波形と同じ時間軸でスペクトログラムを表示する
- 選択中の候補区間を半透明の色で塗る
- 開始・終了位置を明確な縦線で示す
- 候補A、B、Cの境界位置を比較できるようにする
- 時間軸と候補の開始・終了時刻を秒単位で表示する

色だけに依存せず、候補IDと境界線のラベルを併記する。

### 4.3 候補の匿名化

レビュー中はMFA、Julius、Wav2Vec2などの方式名を表示せず、候補A、B、Cとして提示する。

候補の表示順は`utterance_id`、母音位置、評価設定の固定シードから決定し、再実行時に同じ順序を再現できるようにする。保存結果には候補IDと実際の方式名の対応を含める。

### 4.4 再生操作

最低限、次の再生方法を提供する。

- 前後の文脈を含む再生
- 選択中の候補区間だけの再生
- 開始境界付近の短時間ループ
- 終了境界付近の短時間ループ
- 候補A、B、Cの連続再生

文脈用の余白は初期値を前後100msとし、評価設定として固定する。音量正規化やフェードを適用する場合は、全候補へ同じ処理を行い設定を記録する。元音声と区間時刻から再生範囲を動的に決め、レビュー専用の音声を正解データとして保存しない。

## 5. 選択式設問

各候補について次の設問へ回答する。

1. 対象の母音を聞き取れるか: `yes` / `no` / `uncertain`
2. 母音の先頭の切れは利用上問題になるか: `none` / `tolerable` / `problematic` / `uncertain`
3. 母音の末尾の切れは利用上問題になるか: `none` / `tolerable` / `problematic` / `uncertain`
4. 別の母音の核を含むと感じるか: `yes` / `no` / `uncertain`
5. 子音などの非母音成分はどの程度含まれるか: `none` / `tolerable` / `problematic` / `uncertain`

`tolerable`は、切れや非母音成分を知覚できるが、対象母音を後続処理へ利用できる状態を表す。子音との遷移が少し聞こえることだけを理由に候補を不適切とはしない。必要に応じて、開始側・終了側、聞こえた音などを任意メモまたはタグとして保存できるようにする。

候補をすべて確認した後、次から一つを選ぶ。

- 候補Aが最も自然
- 候補Bが最も自然
- 候補Cが最も自然
- 聴感上の差を判断できない
- どの候補も不適切

候補が一つだけの場合は「最も自然な候補」の比較を表示せず、その区間を`accepted`、`rejected`、`uncertain`から選択する。

回答前にすべての候補を最低一回再生するかどうかは、パイロットで操作負担を確認してから決める。未回答を許可する場合も、スキップ理由を記録する。

## 6. 自動振り分けとの連携

UIへ送る対象は次とする。

- 自動検査で`review_required`となった全区間
- 長母音、連続母音、無声化母音の候補
- `auto_agree`から決定的に抜き取った確認用区間

レビュー理由を内部データには保存するが、回答へ影響する詳細なモデルスコアや方式名はレビュー完了まで表示しない。

## 7. 保存形式

回答は追記可能なJSONLまたは同等の構造化形式で保存する。最低限、次を記録する。

```json
{
  "review_id": "jvs001_voiceactress100_001-o-004",
  "utterance_id": "jvs001_voiceactress100_001",
  "vowel_index": 4,
  "expected_phoneme": "o",
  "candidate_id": "B",
  "aligner": "mfa",
  "start_sec": 2.842,
  "end_sec": 3.016,
  "audible": "yes",
  "start_clipping": "none",
  "end_clipping": "none",
  "other_vowel": "no",
  "non_vowel_contamination": "tolerable",
  "review_note": "開始側に先行子音からの遷移が少し聞こえる",
  "preferred_candidate": "B",
  "review_status": "accepted",
  "reviewer_kind": "non_expert",
  "guideline_version": "2",
  "ui_version": "2"
}
```

回答の上書きが必要な場合は履歴を失わず、再レビューであることを識別できるようにする。

ガイドラインv1の回答は履歴として保持する。v2の設問でレビューを行うときは、評価プロトコル、データセット、UIのバージョンを更新し、v1とv2の結果を同じ条件の回答として暗黙に集計しない。

## 8. ぶれを抑えるための要件

- すべてのレビューで同じ時間縮尺と余白を使用する
- 候補ごとに音量や再生速度を変えない
- 方式名、モデルスコア、自動判定結果を回答前に表示しない
- 設問の文章と選択肢の順序を固定する
- 候補の匿名化対応を固定シードで再現する
- `uncertain`と「差を判断できない」を明示的に許可する
- 一部のレビュー単位を重複提示し、回答の再現性を測定する
- キーボード操作と色以外の識別手段を提供する

## 9. 完了条件

- 原音声、期待音素、3方式の候補区間を読み込める
- 波形、スペクトログラム、候補境界を同じ時間軸で表示できる
- 指定した再生方法を同じ条件で実行できる
- 方式名を隠して候補を比較できる
- 選択式回答と候補選択を構造化データとして保存できる
- ページ再読み込み後も未処理・処理済みを識別できる
- 同じ入力と設定から候補順、表示範囲、再生範囲を再現できる

## 10. 実装順序

1. 固定したサンプルデータで波形表示と区間再生を実装する
2. 一つの方式の候補区間を表示する
3. 3方式の匿名化候補を切り替えられるようにする
4. 選択式回答をローカルへ保存する
5. 自動振り分け結果からレビュー対象を読み込む
6. 進捗、再レビュー、結果出力を追加する

評価機能であり本番機能ではないため、初期実装はApple Silicon上でローカル実行できる最小構成を優先する。
