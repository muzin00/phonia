# 半自動母音区間評価ガイドライン

## 1. 目的

MFA、Julius、Wav2Vec2 phoneme CTCが出力する日本語5母音の区間を、専門的な音声学の判断へ過度に依存せず比較する。

評価の中心は機械的に再現できる検査と方式間の一致度とする。人間は、機械が判断できない区間と無作為抽出した確認用区間について、事前にマークされた候補を再生し、直感的な設問へ回答する。

非専門家による確認結果を精密な正解境界とは扱わない。専門家が作成した参照境界がない段階では、「境界精度」ではなく「境界一致度」「抽出成功率」「聴感上の区間品質」として報告する。

## 2. 基本方針

- 人間にゼロから開始時刻と終了時刻を入力させない。
- G2Pで確定した期待音素列を基準に、母音の個数と順序を機械的に照合する。
- 3方式の結果は独立して保存し、評価用の候補を作るために平均または上書きしない。
- 方式名を隠し、候補の表示順をランダム化して確認者の先入観を減らす。
- 自動検査を通過した区間は原則として人手確認を省略し、一部だけを抜き取り確認する。
- 自動検査で不一致や異常を検出した区間を優先して人手確認する。
- 判断できない場合に無理な合否を求めず、`uncertain`として保存する。

### 2.1 母音区間の判定定義

母音区間は、対象母音の音響的な実現を含み、別の母音の核を含まない連続した波形区間とする。音声学的に純粋な母音定常部だけを要求しない。

- 前後の子音との遷移や共調音が聞こえても、対象母音を利用できれば許容できる。
- 子音らしい成分が聞こえることと、別の母音を含むことを分けて判定する。
- 対象母音が利用できないほど切れている場合は不適切とする。
- 異なる母音の核を明確に含む場合は不適切とする。
- 同じ母音が直接連続する`vowel_run`は一つの対象母音区間として扱える。
- 先行子音全体を意図的に含めるモーラ区間とは区別する。

## 3. 入力

評価には次の情報を使用する。

- 原音声
- 発話テキスト
- 人間が読みを確認した期待音素列
- 各方式が出力した生の音素ラベルと開始・終了時刻
- 共通表記へ正規化した音素ラベル

期待音素列は[`data/phonemes/expected.jsonl`](data/phonemes/expected.jsonl)で管理する。`review_status`が`reviewed`になった発話だけを正式な比較に使用する。

## 4. 機械的な検査

### 4.1 構造検査

各方式の出力について次を自動検査する。

- 期待する5母音の個数と順序に対応できる
- 開始時刻と終了時刻が数値である
- `0 <= start_sec < end_sec <= 音声長`を満たす
- 区間が時間順に並んでいる
- 同じ方式内で不正な重複や逆転がない
- 極端に短い区間または長い区間ではない
- 必須のモデル名、バージョン、設定が記録されている

母音長の閾値はパイロット結果を見て固定する。固定前は分布上の外れ値として警告し、即時の失敗とはしない。

### 4.2 音声信号の健全性検査

抽出区間について次を自動計算する。

- 区間長
- RMSまたは同等の音量指標
- 無音に近いフレームの割合
- 前後に追加した余白区間との音量差
- 算出可能な場合は有声音率

無声化母音では有声音率が低くなるため、有声音率だけで失敗とは判定しない。信号指標は異常候補の抽出に使用し、音素の正しさを単独で保証する指標にはしない。

### 4.3 方式間の境界一致度

同じ期待母音へ対応付けた3方式の結果について、方式の全組み合わせで次を計算する。

```text
start_delta(A, B) = abs(A.start_sec - B.start_sec)
end_delta(A, B)   = abs(A.end_sec - B.end_sec)
```

加えて次を記録する。

- 開始境界の最大差
- 終了境界の最大差
- 区間のIntersection over Union（IoU）
- 区間長の差

`10ms`、`20ms`、`30ms`、`50ms`以内で一致する割合をそれぞれ集計する。3方式が一致していても、共通して誤っている可能性があるため、これは精度ではなく一致度として扱う。

### 4.4 自動振り分け

パイロットでは、次の条件をすべて満たす区間を`auto_agree`候補とする。

- 3方式すべてが期待母音へ対応付けられた
- 構造検査で失敗がない
- 開始境界と終了境界の最大差がともに30ms以内
- 音声信号の健全性検査で重大な警告がない

それ以外は`review_required`とする。30msは初期値であり、`10ms`、`20ms`、`50ms`へ変更した場合の件数と結論も確認してから固定する。

## 5. 人手確認画面

人手確認用ツールは、対象母音ごとに次を表示する。

- 発話テキストと確認対象の母音
- 波形とスペクトログラム
- 開始・終了位置を色付きで示した候補A、B、C
- 対象区間の前後100ms程度を含む再生ボタン
- 各候補だけを連続して聴き比べる再生ボタン
- 開始付近と終了付近を短く繰り返す再生ボタン

候補A、B、Cと実際の方式名の対応は画面に表示せず、区間ごとに表示順をランダム化する。対応関係は評価結果へ内部的に記録する。

同じ画面で精密な時刻入力や波形境界のドラッグ操作を必須にしない。

## 6. 人間が回答する項目

確認者は各候補について次の選択式設問へ回答する。

1. 対象の母音を聞き取れるか: `yes` / `no` / `uncertain`
2. 母音の先頭の切れは利用上問題になるか: `none` / `tolerable` / `problematic` / `uncertain`
3. 母音の末尾の切れは利用上問題になるか: `none` / `tolerable` / `problematic` / `uncertain`
4. 別の母音の核を含むと感じるか: `yes` / `no` / `uncertain`
5. 子音などの非母音成分はどの程度含まれるか: `none` / `tolerable` / `problematic` / `uncertain`

`tolerable`は、切れや非母音成分を知覚できるが、対象母音を後続処理へ利用できる状態を表す。例えば、`の`の`/o/`区間で`/n/`からの遷移が少し聞こえても、`/o/`を十分に聞き取れ、別の母音を含まなければ`non_vowel_contamination: tolerable`とする。

最後に、次から一つを選ぶ。

- 候補Aが最も自然
- 候補Bが最も自然
- 候補Cが最も自然
- 聴感上の差を判断できない
- どの候補も不適切

候補が一つだけの場合は候補間比較を求めず、その区間を`accepted`、`rejected`、`uncertain`から選ぶ。確認者には音響用語の判断を求めず、「聞き取れる」「利用できる」「別の母音が入っている」という聴感上の判断だけを求める。

## 7. 人手確認の対象

パイロットの3発話は、確認画面と設問が妥当かを確かめるため全件を確認する。

30〜50発話へ拡張した後は次を確認対象とする。

- `review_required`となった全区間
- 長母音と無声化母音の候補
- 各母音から均等に選んだ`auto_agree`区間
- `auto_agree`全体から決定的に抽出した20%

抜き取り対象は、`utterance_id`と母音位置から計算したハッシュなどを使って毎回同じ集合になるようにする。

## 8. 判定結果

方式ごとの候補を次の状態へ分類する。

- `accepted`: 対象母音を聞き取れ、利用不能な切れがなく、別の母音の核を含まず、非母音成分が利用上問題にならない
- `rejected`: 対象母音を聞き取れない、利用不能な切れがある、別の母音の核を含む、または非母音成分が利用上問題になる
- `uncertain`: 非専門家の聴感では判断できない
- `not_reviewed`: 自動判定のみで人手確認していない

`non_vowel_contamination: tolerable`は`accepted`にできる。子音との遷移が聞こえることだけを理由に`rejected`へ分類しない。

この分類はアライナー方式全体の性能と失敗傾向を集計するためのものであり、個別区間を後続の学習データから除外したり、信頼度や学習重みを付けたりするためには使用しない。後続PoCでは、採用したアライナーが生成し、機械的に学習入力を構成できる全区間を同じ規則で使用する。

方式選定では次を比較する。

- 期待母音との対応成功率
- 構造検査の成功率
- 方式間の境界一致度
- 人手確認した区間の`accepted`率
- 利用上問題になる先頭切れ、末尾切れの発生率
- 別の母音核を含む割合
- 許容可能または問題になる非母音成分の発生率
- 音素別、長母音、無声化候補別の失敗傾向
- 処理時間、安定性、再実行の容易さ

専門家による参照境界がない限り、絶対的な境界誤差や正解率は主張しない。

## 9. 記録形式

人手確認結果はJSONLで保存し、少なくとも次の情報を持たせる。

```json
{
  "utterance_id": "jvs001_voiceactress100_001",
  "vowel_index": 0,
  "expected_phoneme": "a",
  "candidate_id": "B",
  "aligner": "mfa",
  "start_sec": 0.42,
  "end_sec": 0.56,
  "auto_status": "review_required",
  "audible": "yes",
  "start_clipping": "none",
  "end_clipping": "none",
  "other_vowel": "no",
  "non_vowel_contamination": "tolerable",
  "preference": "B",
  "review_status": "accepted",
  "guideline_version": "2"
}
```

画面上の候補IDと方式名の対応はレビュー中には隠すが、保存結果には含める。

ガイドラインv1の`start_clipped`、`end_clipped`、`neighbor_contamination`を使った回答は履歴として保持する。v2の回答を収集するときは、評価プロトコルとデータセットのバージョンを更新し、異なる設問で得た結果を同じ集計へ暗黙に混在させない。

## 10. 品質確認

- `auto_agree`の抜き取り確認で問題が多い場合は、自動振り分けの閾値を厳しくする。
- 同じ区間の一部を再度提示し、回答が大きく変わらないか確認する。
- 候補の表示順を変えても選択傾向が変わらないか確認する。
- `uncertain`が多い条件は、方式の優劣を無理に決めず追加検証へ回す。
- 3方式が系統的に同じ誤りを出す可能性は、後続の話者認証性能または専門家による小規模確認で補う。

## 11. 精密境界が必要になった場合

方式間の差が聴感評価だけでは解消できない場合に限り、問題区間を絞ってPraat TextGridによる精密アノテーションを行う。この作業は初期評価の必須条件にしない。

精密アノテーションを行う場合は、専門知識を持つ協力者への依頼または別途定義した境界基準を使用し、非専門家の選択式レビューと混同しない。
