# JVSデータセット設計

## 1. 目的

JVSの通常発話を、音素別話者表現の学習、検証、テストへ再現可能に割り当てる。
話者リークと元音声の重複を機械的に検出し、学習話者数に対する性能変化と、未知話者の
本人照合性能を評価できる構成にする。

本設計は、JVSの単一かつ統制された収録条件内での成立性確認を対象とする。別日、別端末、
異なる環境に対する評価は、[段階的な検証戦略](validation-strategy.md)の第2段階で行う。

## 2. 使用する音声

初期学習と主要評価には、通常発話だけを使用する。

| サブセット | 用途 | 収録済み発話数 |
| --- | --- | ---: |
| `parallel100` | 学習、登録、主要照合 | 9,997 |
| `nonpara30` | 学習、異文照合 | 3,000 |
| `whisper10` | 初期対象外。後の条件別評価候補 | 1,000 |
| `falset10` | 初期対象外。後の条件別評価候補 | 1,000 |

対象は`parallel100`と`nonpara30`の合計12,997発話、約26.22時間である。
`parallel100`で音声が存在しない既知の3件はmanifestへ含めず、検査レポートの警告として
記録する。

## 3. 話者分割

100話者を次の三つへ分離する。

| 分割 | 話者数 | 用途 |
| --- | ---: | --- |
| train | 70 | モデルのパラメータ学習 |
| validation | 15 | モデル選択、閾値や設定の比較 |
| test | 15 | 設計確定後の最終評価 |

分割はseed `20260926`を使った固定順序で決定する。話者IDの正本は
[`config/dataset-split.json`](config/dataset-split.json)とし、train、validation、test間の
話者重複を禁止する。

testの結果を見てモデルや閾値を選択しない。変更が必要な場合はvalidationで判断し、
testは再評価にだけ使用する。

## 4. 学習曲線

train話者の固定順序から、先頭10、25、50、70話者を使用する。各集合は一つ前の集合を
完全に含む入れ子構造とする。話者数以外の学習条件を固定し、未知話者性能の変化を比較する。

train話者については`parallel100`と`nonpara30`の利用可能な全発話を学習候補とする。
各manifestレコードの`learning_curve_cohorts`に、その話者が含まれる集合を記録する。

## 5. 登録と照合の分離

validationとtestの話者には、次の役割を割り当てる。

| サブセット・発話 | `evaluation_role` | 用途 |
| --- | --- | --- |
| `parallel100`の001〜050 | `enrollment` | 話者プロファイルの登録 |
| `parallel100`の051〜100 | `verification` | 主要な本人・他人照合 |
| `nonpara30`の全発話 | `cross_text_verification` | 登録文と異なる文章による補助評価 |

`parallel100`は全話者が共通文を読むため、発話番号で登録と照合を分けることで同一録音の
再利用を防ぎ、話者間で文章条件を揃える。`nonpara30`は話者ごとに文章が異なるため、
文章条件を統制した主要指標にはせず、異文条件での頑健性を見る補助指標とする。

JVSには収録日やセッションIDがないため、この分離をクロスセッション評価とはみなさない。

## 6. 機械可読成果物

- `config/dataset-split.json`: 固定した話者分割と役割規則
- `data/utterance-manifest.jsonl`: 対象発話と用途を対応付けるmanifest
- `data/dataset-validation.json`: 件数、時間、重複、最低規模の検査結果
- `scripts/build_dataset_manifest.py`: 上記データ成果物の再生成プログラム

manifestは元音声を複製せず、Git管理外の`data/source/`にあるファイルをリポジトリ相対パスで
参照する。JVS音声自体は再配布しない。

## 7. 合格条件

生成結果は、少なくとも次をすべて満たす必要がある。

- 100話者がいずれか一つの分割だけに所属する
- train、validation、testの話者数が70、15、15である
- 10、25、50、70話者の学習集合が入れ子になっている
- manifestの発話IDと元ファイルパスが一意である
- 同一チェックサムの元音声が複数レコードに現れない
- validationとtestの各話者に登録、主要照合、異文照合の発話がある
- すべてのWAVが24 kHz、mono、16-bit PCMで読み出せる
- すべてのWAVに空でない書き起こしが対応する

既知の`parallel100`欠損3件は警告として扱う。これ以外の欠損や上記条件への違反があれば、
検査結果を不合格とする。
