# 母音区間データセットの生成・品質確認結果

## 1. 実行結果

- 実行日: 2026-09-26
- 入力: JVS `parallel100`と`nonpara30`の12,997発話
- G2P成功: 12,997発話
- Juliusアライメント成功: 12,992発話
- 機械的失敗: 5発話（0.038%）

詳細な話者別・評価用途別集計と成果物チェックサムは
[`data/vowel-dataset-validation.json`](data/vowel-dataset-validation.json)を正本とする。

## 3. 品質フラグ

RMSが-50 dBFS未満の`near_silent`を11,522区間（2.432%）で記録した。無音、30 ms未満、
時刻不正、元音声範囲外、読み出し不能は0件だった。

`near_silent`は分析属性として保持し、区間の採否、重み付け、サンプリングには使用しない。
Phase 3ではフラグあり・なしの性能差を固定した評価条件で分析できる。

## 4. 処理失敗

次の5発話はJuliusがアライメント候補を生成できず、学習入力を構成できないため対象外とした。

- `jvs009_nonpara30_basic5000_2571`
- `jvs009_nonpara30_travel1000_0787`
- `jvs009_parallel100_voiceactress100_095`
- `jvs047_parallel100_voiceactress100_085`
- `jvs058_parallel100_voiceactress100_022`

失敗は`Julius search failed: no alignment candidate`として記録し、発話別ログを保持する。
個別区間の人手修正や代替境界の採用は行わない。

## 5. 音素変換上の判断

pyopenjtalkが出力する`v`と`ty`は固定したJulius単音素モデルに存在しなかった。
Julius付属規則に合わせて`v`を`b`へ変換し、`ty`は利用可能な近似音`ch`へ変換した。
変換規則と版は設定、発話別アライメント、run metadataへ記録している。

## 6. Phase 3への受け渡し

Phase 3は`vowel-segments.jsonl`を順次読み、各レコードの`source_file`から
`start_frame:end_frame`を取得する。区間WAVを複製しない`source_slice`方式のため、
約47万個の小ファイルを管理せずに、話者、母音、分割、評価用途を使って入力を構成できる。
