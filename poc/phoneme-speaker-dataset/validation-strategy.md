# 段階的な検証戦略

## 1. 決定

初期PoCでは、JVSによる成立性確認と、許諾済み実環境音声による外部評価を段階的に行う。

- 決定日: 2026-09-26
- 第1段階: JVSを使い、音素別話者表現と学習パイプラインの成立性を確認する
- 第2段階: 第1段階を通過したモデルを、別日・別端末・異なる環境を含む音声で評価する
- 大規模収集: 第2段階で改善可能性を確認してから検討する

JVSの結果だけでプロダクト条件を満たしたとは判断しない。一方、実環境音声を最初から
大規模収集することもしない。制御されたデータで基礎的な問題を切り分けた後に、実環境への
一般化を検証する。

## 2. この順序を採用する理由

JVSは話者ID、書き起こし、音声形式が整理されており、音素区間生成、特徴量、モデル、
損失関数、学習ペア生成などの問題を比較的切り分けやすい。ただし、単一の統制された
収録条件であり、別セッションや実利用環境への頑健性は評価できない。

YouTubeなどの公開動画は実環境に近い多様性を持つ一方、話者同定、複数話者の分離、
BGMや残響への対応、文字起こし、重複除去、利用許諾の確認が必要になる。この状態で
学習に失敗すると、データ生成工程とモデルのどちらに原因があるか判断しにくい。

このため、第1段階ではJVSをプロダクト性能の証明ではなく、モデルとパイプラインの
成立性テストとして使用する。

## 3. 第1段階: JVSによる成立性確認

### 3.1 検証内容

- train、validation、testの話者を完全に分離する
- 登録用発話と照合用発話を分離する
- 学習話者数を段階的に変え、学習曲線を取得する
- 学習損失、未知話者に対する認証指標、母音別指標を記録する
- データ量、アライメント失敗、品質フラグと性能の関係を記録する

学習話者数の具体的な段階は、固定するtrain話者数を決定した後に設定する。候補として
10、25、50、利用可能な最大話者数を用いる。

### 3.2 結果の解釈

| 観測結果 | 判断 | 次の作業 |
| --- | --- | --- |
| 学習データ上でも識別できない | モデル、特徴量、区間生成、学習実装の問題を疑う | 実装と方式を見直し、大規模収集には進まない |
| 学習話者では識別できるが未知話者では低性能 | 過適合または話者多様性不足を疑う | 学習曲線とエラーを分析する |
| 話者数を増やすほど未知話者性能が改善する | 多話者化に改善余地がある | 第2段階へ進む |
| JVS内で十分な性能を得る | 制御条件下で成立した | 第2段階へ進み、実環境で評価する |

JVSで低性能だったという事実だけでは、直ちにプロジェクトを終了しない。学習データ上の
性能、未知話者性能、話者数に対する学習曲線を合わせ、方式の問題と規模不足を区別する。

## 4. 第2段階: 実環境音声による外部評価

### 4.1 初期規模

最初から1万話者規模を目指さず、20〜50話者程度の小規模な外部評価セットから始める。
各話者について、可能な限り次を満たす音声を用意する。

- 複数の収録日または収録セッション
- 複数の端末、マイク、距離または環境
- 登録用と照合用で異なるセッション
- 話者本人を確認できる情報
- 音声の研究利用、モデル学習、評価に必要な許諾

第2段階の主目的は大量学習ではなく、JVSで成立した表現が収録条件の変化に耐えるかを
評価することである。

### 4.2 結果の解釈

| 観測結果 | 判断 | 次の作業 |
| --- | --- | --- |
| JVSでは高性能だが実環境で低下する | 収録条件への過適合を疑う | 許諾済み実環境データを学習へ追加する |
| 実環境データの追加で改善する | データ多様性の拡張が有効 | 話者数とセッション数を段階的に増やす |
| 追加しても改善しない | 特徴表現または方式の限界を疑う | モデルと評価設計を再検討する |

## 5. YouTubeの位置づけ

YouTube上の公開動画を、そのまま継続的な学習データ供給源とはみなさない。公開されている
ことと、音声の取得、保存、加工、モデル学習への利用が許諾されていることは同義ではない。

YouTube相当の実環境音声が必要な場合は、次を優先する。

1. 話者または権利者から用途を明示した許諾を得る
2. 可能であれば、動画サイトから抽出せず元音声ファイルの提供を受ける
3. 話者、セッション、収録条件、許諾範囲をmanifestへ記録する
4. 削除依頼や利用停止に対応できる由来管理を行う

YouTube由来データの利用を改めて検討する場合は、収集を開始する前に、プラットフォームの
利用規約、著作権、話者本人の権利、想定する商用利用を確認する。

## 6. 大規模化の判断

数千〜1万話者規模への拡張は、次の条件を満たした後に判断する。

- JVSで音素別話者表現の成立を確認できている
- 実環境の外部評価セットで性能差を測定できている
- 実環境データを追加したときに改善傾向がある
- 話者同定、セッション分離、品質検査を再現可能な工程として実行できる
- 収集、保存、学習、将来の製品利用に必要な権利を確保できる

大規模化の判断には、単一の最終精度だけでなく、話者数とセッション数に対する学習曲線、
データ作成コスト、誤ラベル率、利用可能な権利範囲を使用する。
