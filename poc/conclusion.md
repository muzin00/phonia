# 音素ベース音声認証 PoCの最終結論

2026年10月11日時点の初期PoCと追加検証を総括する。

**音素単位の特徴を使う本人照合は技術的に成立し、登録量・音素構成・スコア統合によって改善する条件が見つかった。一方、既存方式より優れることと、実際の録音環境での有効性は確認できていない。初期PoCを完了し、構成を固定したプロトタイプと新しい実録音での評価へ進む。**

中心仮説は「同じ音素で比較条件を揃える方が、発話全体の表現より安定して話者特徴を学習できる可能性がある」だった。本人照合の実装と実測は達成したが、発話全体方式に対する優位性を実証するには至らなかった。

## 技術的に確認できたこと

録音音声と発話テキストから音素区間を抽出し、共通encoderの学習、ユーザー別プロファイルの登録・保存、同じ音素の照合、スコア統合、本人認証の評価まで実装した。新しいユーザーの登録時に共通モデルを再学習する必要はない。

初期の5母音から、学習可能な全36音素まで拡張した。音素別encoderは65,920パラメータである。ただし、音素アライメントを含む処理全体の速度・メモリ・利用者の録音負担が既存方式より優れるかは、次段階で測定する。

モデル・入力・validation閾値を固定してtestへ適用し、スコアと指標の再計算、音声hashと話者ラベルの分離、対応付き話者bootstrapによって実験結果を検証した。

根拠は[ユーザー登録](phoneme-user-registration/README.md)、[本人照合](phoneme-verification/README.md)、[発話単位の評価](phoneme-verification-evaluation/evaluation-results.md)、[全36音素学習](phoneme-all-training/README.md)を参照する。

## 既存方式との比較

Phase 7では同じ登録元WAVと照合発話を使い、境界内母音・文脈付き母音・発話全体ECAPAを比較した。登録各母音10区間、発話全区間を取得する主条件のtest EERは次のとおりだった。

| 方式 | 通常文EER | 別文EER |
| --- | ---: | ---: |
| 境界内母音 | 1.526% | 1.257% |
| 前後20 msの文脈付き母音 | 1.497% | 1.239% |
| 発話全体ECAPA | 0.029% | 0.222% |

**この方式比較ではECAPAが優位だった。** 母音不足を含む全入力FRRもECAPAの方が低かった。モデル規模・事前学習・内部で使う音声量は異なるため、音素分割そのものの効果を示す比較ではない。後続の全36音素・Transformerの構成では、同じ条件でのECAPA再比較を行っていない。

根拠は[Phase 7の結果と比較条件](phoneme-baseline-comparison/evaluation-results.md)を参照する。

## 改善実験から得た結論

以下は各実験内での比較である。実験ごとにモデル・発話集合・使用音声量が異なるため、行をまたいで優劣を順位づけしない。EERは低いほどよい。

| 検証 | 通常文test EER | 別文test EER | 結論 |
| --- | ---: | ---: | --- |
| [同じ7音素モデルで5母音にm/nを追加](phoneme-consonant-evaluation/interpretation.md) | 2.395% → 1.333% | 1.509% → 0.889% | 実使用時間を揃えても改善する条件があった。全7音素を使える共通入力での結果。 |
| [5母音から全36音素を学習](phoneme-all-training/interpretation.md) | 1.924% → 1.769% | 1.859% → 1.531% | 観測値は低下したが、差の95%区間は0を含んだ。 |
| [全36音素モデルの登録上限10 → 20 → 30](phoneme-all-enrollment-scaling/interpretation.md) | 1.769% → 1.361% → 1.497% | 1.531% → 1.221% → 1.020% | 別文は低下し、通常文は非単調。10 → 30差の95%区間は両方とも0を含んだ。 |
| [等重みからclean学習Transformerへ変更](phoneme-transformer-fusion/interpretation.md) | 1.497% → 1.186% | 1.020% → 0.941% | 3 seed平均は改善した。差の95%区間は0を含んだ。 |
| [ノイズ・欠損を学習に追加した場合のノイズ入力](phoneme-fusion-augmentation/evaluation-results.md) | 3.356% → 1.374% | 3.401% → 1.166% | 3 seedとも改善。通常文の前回との差の95%区間は0を含まなかった。 |
| [同じ追加学習によるclean入力](phoneme-fusion-augmentation/evaluation-results.md) | 1.186% → 1.429% | 0.941% → 1.136% | 3 seed平均は悪化し、clean性能との両立は未達だった。 |
| [同じ追加学習による子音50%欠損入力](phoneme-fusion-augmentation/evaluation-results.md) | 1.523% → 1.769% | 0.887% → 1.166% | 3 seed平均は悪化し、欠損への改善も確認できなかった。 |

m/nの主比較では、通常文FRRが4.571%から2.095%に低下し、差の95%区間は0を含まなかった。実使用時間を揃えた条件でも、本人拒否を減らす結果が得られた。

音素を追加すること自体が、常に改善につながるわけではない。[固定時間で5 → 7 → 10 → 14種類を比較](phoneme-count-scaling/interpretation.md)した実験では改善傾向を確認できず、[全候補をランダムに追加して再試験](phoneme-greedy-selection/interpretation.md)した探索も、validationの改善がtestへ移らなかった。

[学習データ追加](phoneme-training-data-expansion/evaluation-interpretation.md)と[60,000更新までの学習量比較](phoneme-training-budget/interpretation.md)では、一部指標の改善があっても、総合的に一貫した向上は確認できなかった。「良質なデータや音素を増やせば必ずスケールする」という結論には至っていない。

[音素ごとの話者依存性分析](phoneme-speaker-dependence/interpretation.md)では、音素間の差と別話者で再現する傾向が見つかった。ただし、測定したのはembeddingの話者依存性であり、解剖学的な生体依存度ではない。無声音を一律に低い群へ分ける仮説も支持されなかった。

## データ品質と入力不足

区間の機械検査だけでなく、実際の音を試聴することが学習データの採用判断に役立った。ユーザーの聴取所見を受け、後続の子音・全音素学習にはJVSとCommon Voiceを使用し、SRC4VCを外した。SRC4VC全体の品質や、以前の学習結果の原因を確定した判断ではない。[学習データの採用手順](../docs/training-data-adoption.md)を残した。

5母音必須の構成では、短い発話や音素不足で照合できない入力がある。[4母音以上へ緩和した実験](phoneme-missing-vowel-evaluation/interpretation.md)では本人拒否が減った一方、他人受入も増えた。EERだけでなく、入力不足を含むFAR・FRRと登録・照合の手間を併せて評価する必要がある。

総括後の[全36音素モデルでの母音不足対応](phoneme-all-missing-vowel-evaluation/interpretation.md)でも、入力不足の救済効果を確認した。
登録上限30区間・等重みで5母音必須から4母音以上へ緩和すると、全入力FRRは通常文4.400→2.400%、別文14.222→2.667%へ下がった。
一方、全入力FARは0.410→0.419%、0.714→0.810%へ上がり、FARを維持した改善とは扱わない。
別文の追加他人受入6件のうち5件は /u/ 欠損だった。3母音以上かつ母音と子音を合わせて5種類以上では別文FRRが1.556%になったが、追加救済は4話者・5発話だけである。
既存Transformer 3 seedでもFRRは低下した一方、4母音以上の別文FAR平均は1.063%となった。
新規学習なしの探索的検証で、独立評価へ持ち込む候補を具体化した結果である。

さらに[新規Common Voice話者のholdout評価](phoneme-missing-vowel-holdout/interpretation.md)まで完了した。未使用60 client_idを校正30・test30に分け、各話者20発話で登録し、30発話を照合した。
5母音必須から4母音以上への緩和で、test全入力FRRは44.222→23.444%、FARは0.441→0.640%となった。FRR差の95%区間は[−24.889, −17.000] pp、FAR差は[+0.071, +0.402] ppで、入力不足の救済と他人受入増加の両方が再現した。
FARの95%区間上端とFAR増加幅が事前の研究用基準を満たさず、**この受付条件緩和を現構成へ単純導入する案は採用しない**と結論づけた。
JVSの閾値を移植した4母音FARは7.165%だった。新しい校正話者を使っても本人拒否が23.444%残り、母音不足の救済だけでは識別・校正の一般化を解決できていない。

## 結果の適用範囲

初期の性能評価と大半の追加実験は、統制されたJVS収録のvalidation/test各15話者に基づく。追加実験には既に参照したtestを繰り返し使っている。母音不足対応については、新規のCommon Voice校正30・test30話者ラベルで追加評価し、救済効果と他人受入増加を確認した。これは音素方式全体のECAPAへの優位性や、別日・別端末での性能保証を示すものではない。Common Voiceのclient_idと実在人物の対応、およびJVSとの人物重複は不明である。

Transformerの3 seed平均は、3モデルを組み合わせた認証システムではない。また、観測値の改善と、話者bootstrapによる差の確証は区別した。性能差は各実験の条件に対するものであり、実環境全般へ一般化しない。

## PoC完了と次段階

**初期PoCと主要な改善探索はここで区切る。** 技術的な成立、改善する条件、既存方式との差、入力不足とノイズへの課題を把握できたため、次に進む判断材料は揃った。既存方式への優位性を実証するという研究仮説は未確認として残す。

次段階は、録音から登録・照合まで動くプロトタイプを使った実録音評価とする。

1. 音素方式のモデル・音素集合・登録方式・統合方法を固定し、ECAPAを比較対象として残す。採用を過去のtest最良値だけで決めない。
2. 新しい話者を含む録音を集め、同じ人の登録と照合を別日・別端末で行う。録音量と収録条件を記録する。
3. 評価前に許容FAR・FRR、録音時間、処理時間の基準を決める。新しいtestをモデルや閾値の調整に使わない。
4. 精度、照合不能率、登録の手間、アライメントを含む処理時間を測り、実利用に向けて音素方式を継続するか判断する。

次段階の実装と録音収集は、この総括時点では開始していない。
