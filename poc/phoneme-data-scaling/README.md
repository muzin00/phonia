# 話者数・発話数の拡張検証

2026-10-12。[Transformerの更新数比較](../phoneme-transformer-budget/README.md)を終え、同じ構成に渡す学習データを増やす次の候補集合を固定した。利用者の「学習セットが決まったらレビューUIで品質を確認するから先に進まず教えて」という指示に従い、選定時点でいったん通知した。その後の「続けて」を受け、追加集合の一部から[100区間のレビューUI](review.md)を準備した。続く「OK 確認した進めて」を受け、[全量処理と学習比較](expansion.md)を開始した。個別回答の保存や定量的な品質率は作成していない。

全量処理と学習・評価を完了した。両方追加420のTransformerでは、現状280に比べJTube EERが1.129→0.801%（相対29.0%改善）、Common Voiceが3.905→3.840%、JVSが1.108→1.150%。発話追加だけでは平均EERが3コーパスとも悪化した。新しい話者も加える方向に改善の手掛かりがあるが、単調な改善ではなく、JTubeの固定閾値での誤受入率は増えている。条件別・encoder単体・最終checkpoint・FAR/FRRと限界は[結果の詳細](expansion.md#学習評価結果)を参照。

## 選定した4条件

元の280ラベルはJVS70・Common Voice70・JTube140。元の学習manifestと特徴量を保持し、追加候補だけを別manifestに保存した。追加量は音素抽出前の発話ファイル数であり、採用音素区間数や音声時間ではない。

| 条件 | 話者ラベル数 | 追加CV発話 | 追加JTube発話 | 追加発話合計 |
| --- | ---: | ---: | ---: | ---: |
| 対照 `baseline280` | 280 | 0 | 0 | 0 |
| 既存話者の発話追加 `utterances280` | 280 | 3,500 | 2,100 | 5,600 |
| 新しい話者の追加 `speakers420` | 420 | 3,500 | 2,100 | 5,600 |
| 両方を追加 `combined420` | 420 | 7,000 | 4,200 | 11,200 |

420ラベルはJVS70・CV140・JTube210。発話追加だけの条件と話者追加の条件で、コーパス別の追加発話数を揃える。両方の条件は互いに重複しない追加集合の和である。発話長・実際に残る音素数・録音条件・コーパス内のラベルごとの発話分布は一致しないので、純粋な話者数の因果効果とは扱わない。

## 追加集合と選び方

- **既存CV話者の追加発話**：従来の70 clientラベルのうち40ラベルに、未使用のtrain発話が3,527件あった。そこから固定seedの話者順・発話順で各話者を順番に取り、3,500件を選定した。
- **既存JTube話者の追加発話**：元の140ラベルの発話順を維持し、最初の50件に続く最大100件までを候補にした。137ラベルに5,591件が残っており、同じく各話者を順番に取って2,100件を選定した。
- **新CV話者**：現在の学習70・評価60 clientを除き、日本語テキスト付きtrain発話50件以上の107候補から70ラベルを固定seedで選択。各50件、計3,500件。
- **新JTube話者**：現在の学習140・校正20・test20ラベルと公式testを除き、日本語リストで30件以上の77候補から70ラベルを固定seedで選択。各30件、計2,100件。50件以上という旧条件では未使用ラベルが4件しか残らないため、新ラベルの最小発話数は30件へ変更した。この変更分も次の品質確認の対象とする。

原配布目録の同一パスと、既存の選定済みパスとの重複は除外した。元の評価用ラベル集合と追加集合の重複は0。全量処理後、使用可能な追加10,633波形と既存学習・評価の参照元32,006波形、および追加波形同士のPCM SHA-256を比較し、完全一致は0件だった。近似コピーや実在人物のコーパス間重複は不明。

Common Voiceは既存の固定revisionの日本語client単位データ（CC0-1.0）を再利用し、配布のtrain splitだけから選定した。JTubeは元のver1.1 ZIP目録、Japanese.lst、ETag、サイズと取得条件を保持する。発話の単位と話者ラベルを実在人物の一意性と同一視しない。

## レビュー後に進める処理

追加した4集合を識別できる形でレビュー用音声・音素区間を準備した。既存と同じ音素抽出・QC規則を使い、固定160発話内の失敗を別の発話で補充していない。レビュー対象は新規CV・新規JTube・既存CV追加・既存JTube追加から各25区間。以前のレビュー結果や「OK」を、この新セットの確認済み記録として流用しない。

品質確認後に全入力を処理し、実際の使用可能ラベル数・音素支持数・時間・除外率を確認してから、音響encoderとTransformerの両方の学習条件を固定する。encoderを元のまま固定して追加データをTransformerだけに渡す比較にはしない。現在の校正/test集合は学習に転用しない。

選定時の420は抽出前の候補ラベル数であり、学習可能数の保証ではなかった。全量処理後のencoder対象は420ラベル、登録・照合条件を満たすTransformer対象は415ラベルとなった。別の話者・発話の補充はしていない。

## 再現と保存先

設定は[config.json](config.json)。成果物は`artifacts/phoneme-data-scaling/candidates420-20261012-v1`。

```sh
poc/phoneme-alignment-evaluation/.venv/bin/python poc/phoneme-data-scaling/selection.py
poc/phoneme-alignment-evaluation/.venv/bin/python poc/phoneme-data-scaling/audit_selection.py
```

`existing_cv.json`・`existing_jtube.json`・`new_cv.json`・`new_jtube.json`に追加対象を保存する。`selection-freeze.json`は元の入力hash、話者・発話選定seed、4条件のラベル集合、対象パス、CVのshard/row、JTubeのZIP内位置・CRC、評価用ラベル一覧を保持する。候補音声そのものの新しいhashは取得時に記録する。

新規3テストで評価話者の除外、話者を順番に使う抽出と不足時の停止、凍結出力の上書き防止を確認した。選定監査も完了し、全11,200件（CV7,000・JTube4,200）を元Parquet・ZIP目録に照合した。件数・集合の包含関係・凍結hashが一致し、評価用ラベルとの重複と既存選定パスとの重複はいずれも0だった。結果は`selection-audit.json`に保存した。全量処理・波形重複検査・学習の実行方法と保存先は[expansion.md](expansion.md)に記載した。元データの音声bytesをデコードする処理や、学習を開始するコマンドは上記の選定コマンドには含めない。
